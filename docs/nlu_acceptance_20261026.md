# 意图理解与容错重构验收

2026-10-26。已在本地工作区完成。按用户任务书重构理解入口，默认网页、SSE 和经典编排共用理解器；没有重写检索、rerank 或记忆核心。

## 行为与改动

- 身份、能力、问候、致谢和库外请求有明确分支，不再被强制送入菜谱检索。
- 输入保留原句，再做全半角、空白、繁简与孤立噪声规范化。模型一次输出意图、槽位和上下文改写信息，程序核对候选与序数。
- 菜名、章节与食材采用分级匹配；原文和图片共用章节结果，接近候选才澄清，中置信匹配显示理解说明。
- 推荐未知条件返回一条问题和可点选选项；不再返回 None。已支持的明确条件、输出要求、数量和排除列表贯穿实际工具执行。
- 完整推荐不因为可选食材缺失而多问；原文已有明确答案的命名问题不被模型臆造的章节选择卡住。
- 记忆派生口味和本轮明确口味继续区别处理；M0/M1 的上下文边界、禁用记忆、授权、确认、RLS 与硬约束校验保留。
- 两个页面支持澄清按钮和理解说明；缓存异常/非法记录不阻断模型，日志不记录问句或槽位原文。

实现入口：`src/nlu/`、`config/nlu.yaml`；接入点：`src/agent/{engine,tools}.py`、`scripts/langchain_service_worker.py`、`scripts/cookbuddy/pipeline.py`。原文/图片改动在 `scripts/recipe_tools.py`；未知条件处理在 `scripts/preference_recommendation.py`。依赖版本已在 requirements 文件及锁文件登记。

## 实际验证

- 后端全量：**825 项全部通过**，真实 PostgreSQL / Milvus 集成开关已开启，耗时 179.973 秒，无跳过。包含隔离、记忆确认、硬约束、序号、原文、图片、整餐规划等既有回归。证据：`eval/nlu/verification/backend.txt`。
- 前端：**32 项通过、0 失败**。证据：`eval/nlu/verification/frontend.txt`。
- 真实 ChatEngine 七轮：身份、选菜、标准章节、口语章节、推荐、带噪声排除、库外请求全部通过。身份与库外请求工具数为 0；两种章节逐字证据相同；被排除菜未重新出现。证据：`eval/nlu/engine-acceptance.json`。
- 三个原问题先做失败回归，红测试保留在 `eval/nlu/baseline-regressions.txt`。新增 NLU 回归覆盖超时/低置信、缓存异常、混输/同音、模糊候选、数字保护、未知条件、重复澄清、日志隐私和记忆口味继承。

## 鲁棒性评测

168 条、42 条基础样例，固定种子 20261026；扰动包括语气词、尾数、表情、空格、同音字、删字、全半角和繁简。数据、脚本、原始及最终报告保存在 `eval/nlu/`。

|---|---:|---:|
| 意图准确率 | 20.83% | 98.81% |
| 槽位 F1 | 3.96% | 94.86% |
| 误拦率 | 4.17% | 1.19% |
| 不必要追问率 | 0.00% | 0.00% |
| 应追问召回率 | 18.75% | 100.00% |
| 扰动稳定性 | 88.10% | 97.62% |

本轮日常对话两类意图准确率均为 100%。误拦率、不必要追问率以本夹具总条数为分母；这些是理解路由/槽位指标，不是完整菜谱答案准确率。2 条虚构菜名表达未能稳定进入“库中未找到”分支，而是进入友好未知/库外分支，已保留失败记录，没有删题或反复挑选最佳结果。模型结果有波动，`cold-report.json` 等较早运行仅作历史证据，最终以 `final-report.json` 为准。

基线是重构前工具与入口规则的组件对照，**不是旧系统端到端准确率**。重构前原文工具快照保存在 `eval/nlu/baseline/recipe_tools_snapshot.py`，SHA256 与报告一致；重新运行的 `baseline-reproduced.json` 已验证指标一致。最初夹具及最初基线没有覆盖写，后因真实目录存在多种红烧肉版本，最终金标允许菜名澄清，并用同一最终夹具重算快照基线。

## 延迟、成本和任务书偏差

本次带全新缓存命名空间的实时评估 P50=29.00ms、P95=2325.99ms。168 条中 59 条走模型、104 条命中本轮内规范化后相同的缓存，不能称为 168 条全冷调用。实际 62 次成功返回的模型响应，输入 42264 tokens、输出 7215 tokens；失败且供应商未返回 usage 的尝试不包含在这些 token 数内。端到端 trace 的 HTTP 尝试计数另有服务计量。没有可靠单价，因此不编造金额。

- **P95 增量 ≤500ms 未达标/未认证**：当前供应商首次理解为秒级，混合路由耗时已超出 500ms；没有同负载旧系统端到端基线，不能把组件耗时差宣称为生产增量。缓存报告独立保留，未用它替代首次调用延迟。
- 路由配置默认复用当前供应商模型，避免擅自换供应商或密钥；可通过 `router.model` 配置更快模型，但需要重新验证质量。
- L6 的语义选择与上下文理解合并；匹配模块提供候选消歧接口，生产不会为每个名称再独立增加一次模型调用。
- 暂不宣称完整语义引用准确率验收通过。已执行逐字来源、引用元数据及真实检索回归。
- 每阶段都执行过全量测试与检索对照；中间出现的兼容回归在最终阶段修复。没有把中间未通过的阶段写成全部通过。
- 为容纳最多两次 3 秒理解请求和必要的名称升级，prepare 预算由 8 秒改为 12 秒，整轮仍受原 30 秒总预算限制。
- 三处旧测试预期按新行为更新：未知条件由 None 改为澄清；不存在的章节由工具失败改为选项；“再清淡点”无法核实的条件由泛检索改为澄清。原安全断言、逐字依据和隔离测试未放松。
- 纯规则离线评估与实时模型评估分开：离线误拦率仍为 5.95%，不能替代实时质量结论。模型不可用时保证有用/友好降级，不保证与成功模型语义等价。

## 复现

需使用已安装依赖的 Python 环境，以及本项目现有 PostgreSQL、Milvus、检索索引与模型配置。全部真实验收使用随机隔离测试用户，并在结束后清理自己的数据。

```bash
PYTHON=/opt/anaconda3/envs/py3.12.11/bin/python
COOKBUDDY_INTEGRATION_TESTS=1 "$PYTHON" -m unittest discover -s tests
node --test tests/test_answer_rendering.cjs
make eval-nlu PYTHON="$PYTHON"
make eval-nlu-live PYTHON="$PYTHON"
"$PYTHON" eval/nlu/check_grounding.py --before eval/nlu/baseline/recipe_tools_snapshot.py --out eval/nlu/grounding-report.json
"$PYTHON" eval/nlu/run_acceptance.py
```

复算组件基线：

```bash
"$PYTHON" eval/nlu/evaluate.py --legacy-tools eval/nlu/baseline/recipe_tools_snapshot.py --out eval/nlu/baseline-reproduced.json
```

`make eval-nlu` 是无需模型的兜底评测；`make eval-nlu-live` 才调用真实理解模型。评测会写报告文件，历史交付报告建议先保留副本。
