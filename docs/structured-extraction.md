# 菜谱结构化与小批量自动抽取

## 本轮目标

把三篇已接入样本与新的自动抽取草稿放在同一个0.2格式中，用可重复的检查判断抽取是否可信。试验批次为5篇，不进行全库自动抽取或重写Milvus。

## 为什么这样组织

一道菜的原料表、计算和步骤可能不一致。若只存一个“必需”标签，会遗漏步骤用料，也可能把可选项或复杂版本用料算成必补。因此先保存各章节的观察，再根据版本和用途判断，而不是让模型直接生成一张最终采购清单。

机器能检查行号和逐字原文，却不能仅靠引用存在就证明食材分类正确。本轮同时使用结构检查、预先阅读原文制定的边界检查、另一次模型复核。当前抽取与复核使用不同模型，但仍存在共同犯错的可能；通过状态表示检查过的草稿，不表示人工已全面批准。

## 统一格式0.2

正式字段定义见[JSON Schema](recipe-schema-v0.2.json)，运行时使用`scripts/recipe_schema.py`校验数据和真实源文件。运行不要求安装额外Python库。

| 字段 | 用途 |
|---|---|
| `recipe_id` / `title` | 稳定标识与原文菜名 |
| `source` / `source_sha256` | 原文件路径和版本；原文变化后旧结果失效 |
| `entities` | 食材、调料、工具、中间产物、成品分别记录 |
| `canonical_name` / `aliases` | 名称与有依据的局部别名，不自动推广全库；试验清单中人工指定的回指映射另记录来源行 |
| `observations` | 每次章节观察，保留属性、阶段、版本、条件、用途和原始数量 |
| `observation_id` | 指向一条具体观察；不能只用食材名代替依据 |
| `source` / `section` / `start_line` / `end_line` / `quote` | 每条观察的真实出处，程序从原文件构建 |
| `alternative_groups` | 明确替代或可混用关系；组合列表不能误当替代。同一实体的多个关系保留在`alternative_group_ids`，`alternative_group`保留兼容主关系，不能把不同版本的关系当作同时采购要求 |
| `issues` | 章节漏项、条件和数量差异，不擅自改原文 |
| `extraction` | 人工或模型抽取、模型名、提示版本、输入哈希、文本处理方式 |
| `validation` | 结构状态、语义检查状态、未解决警告分别记录 |
| `activation` | 是否用于正式样本问答；与检查通过状态分开 |
| `answer_policy` / `version_preparation` | 已整理的回答规则和版本备料方案；新自动草稿默认为null / 空列表 |

未知属性明确填`null`，不猜测数量或默认版本。数量保留原文，模型抽取的数量必须出现在它引用的连续原文中，并与该条目直接关联。模型把计算数量放进原料表时，程序仅在其他原文行中直接找到该名称与数量的绑定关系后另建“仅提及”观察，不转移必需/可选/版本属性；多处同量都保留，不能累加。时间、温度不会变成水量。替代组的共同数量不按每个成员重复累加。

三篇原有样本已经迁移，事实、别名和回答逻辑保持兼容。[迁移回归结果](../data/structured/schema-migration-regression.md)重放此前真实检索与重排结果，重新运行回答及来源检查，避免为了验证字段迁移重复调用模型。

## 自动抽取流程

1. 从固定试验清单读取菜谱，给原文逐行编号；只读取Markdown文本。
2. 使用现有硅基流动配置与`Qwen/Qwen3-32B`抽取实体、观察、替代组和章节差异；`Qwen/Qwen3-8B`另一次请求复核。
3. 程序用模型提供的原文片段在文件中唯一定位行号，再填入路径、章节、逐字摘录和稳定ID；检查字段、范围、源文件哈希及组关系。
4. 使用试验清单中的独立边界检查核对易错条目，再用复核模型另一次请求核对原文与抽取结果（仅传必要语义字段，原文不重复多份发送）。
5. 发现问题时一次反馈全部独立字段问题，并给出具体行号；每次运行最多两次新抽取请求。失败草稿有完整原始返回时先重放检查，不重复请求；重放也保留记录。失败或未解决项保留记录；重跑前的原始返回归档到每篇目录的history中。
6. 保存草稿、每次原始返回、模型复核和检查报告。所有模型抽取草稿的`activation.enabled`为`false`。

请求使用流式接收，避免较长输出在等待完整响应时超时；不使用思考模式与JSON输出模式的组合。抽取请求采用temperature=0.6、top_p=0.95，避免零温度解码的重复风险，参考[Qwen3-8B官方模型说明](https://huggingface.co/Qwen/Qwen3-8B)。流式、思考预算和输出截断行为参考[硅基流动对话接口](https://docs.siliconflow.cn/docs/api/chat-completions-post)。只保存最终内容，不保存请求头或密钥。网络临时错误有限重试（30/45秒间隔）；输出截断或无效JSON保留原始返回。网络失败不能被当成语义错误去让模型“修正菜谱”；已得到合法草稿但复核接口不可用时标为needs_review，不能伪装成通过。

## 五篇试验的重点

| 菜谱 | 预先设定的检查重点 |
|---|---|
| 可乐鸡翅 | 料酒/啤酒替代；计算出现的老抽；步骤的水和油；老抽调色可选 |
| 蒸水蛋 | 盐不能遗漏；锡纸/保鲜膜为工具；附加佐料可选；热水与温水的原文差异 |
| 空气炸锅面包片 | 空气炸锅为工具；温度、时间与营养表字段不是采购条目 |
| 西红柿炒鸡蛋 | 糖、葱花、醋、番茄酱和添汤用水的可选范围；蛋液为中间产物 |
| 凉皮 | 组合列表逐项拆分；绿豆芽不能遗漏；盆、碗、盘子、蒜臼为工具；辣椒油可选 |

清单位于`data/structured/extraction-pilot-manifest.json`。这不是自动结果的完整人工标注，只是本次有针对性的边界检查，不能由此计算全库准确率。

## 使用方式

在项目目录执行：

```sh
python3 scripts/verify_structured_recipe_pilot.py
python3 -m unittest discover -s tests
python3 scripts/extract_recipe_pilot.py
```

`--model Qwen/Qwen3-8B`可试较小的抽取模型；`--review-model Qwen/Qwen3-32B`可改复核模型。默认32B抽取、8B复核，正式问答生成配置仍是8B。

`--limit 1`可只跑第一篇，试验最多5篇。已通过草稿在输入哈希、模型、提示版本、格式和边界清单一致时复用缓存；`--force`会重新调用模型。失败或待检查记录会重新尝试。接口密钥继续从本地配置读取，无需写在命令或聊天中。

输出：`data/structured/extraction_pilot/review.md`和`summary.json`，每篇目录保留`recipe.json`、`result.json`及各次原始抽取。返回码0表示此次批次全部草稿通过，2表示批次中有失败/待复核，1表示批次配置或运行本身未完成。

## 尚未覆盖

图片链接及说明仍保留在原文和已有图片清单中。本轮不做OCR、图片描述或图片向量，使用名称带VL的Embedding模型也没有改变这一点。模型只接收文本。

库存数量换算、具体奶制品含脂量、过敏/忌口和完整工具充足性不在本轮抽取验收范围。已有三篇回答仍有专门规则；新草稿不会仅因结构检查通过就自动获得同样的推荐能力。
