# 搜索图文融合 · 2026-10-15

普通菜谱问答、食材推荐以及故障时的原文候选，返回前自动关联已有来源的本地原图，不需要用户另发“查看图片”。保留独立找图能力用于精确图片请求。前端将文字、原文和图片放在对应菜谱卡片；同一来源的已核验问答、原文与图片工具结果合并，入口统一为“查看完整图文”。

实现：先完成文字检索和原文核验，再按 source 与 section 查当前媒体索引，并校验图片哈希、原文件哈希、引用行。问答每份来源最多4图，推荐每份最多2图，总计最多8图，最多4份来源；没有本地图时保留文字。图片校验失败只记录图片错误，不改变文字回答的核验状态。图片不增加模型调用，也不被当作用量、温度或熟度事实。缓存命中后仍重新核验图片，不复用旧图片缓存。外部图片仅保留链接，不自动下载。

新增5项测试，覆盖普通问答自动配图、推荐图数限制、坏图不阻断文字且不复用缓存图、来源/章节隔离、同名来源待选时不擅选图。完整326项测试通过，JavaScript语法检查通过。

浏览器用普通提问“基础牛奶面包的酵头怎么制作？”实测，不包含图片请求，结果自动关联4张图片并与原文混排。该次文字问答因原菜谱向量服务不可用进入已核验原文候选降级，界面保留“部分完成”的状态，没有把候选声称为生成答案。图文自动关联已在这条真实链路中确认；不以此声称修复了原菜谱向量服务。截图：data/processed/cookbuddy-acceptance/search-media.png。
