# 菜谱聊天前端验收（2026-10-14）

入口：http://127.0.0.1:8080/ 。使用本地 HTTP 服务，直接打开 HTML 文件无法调用接口。

## 已实现

- 聊天式多轮问答，历史回答不覆盖；Enter 发送、Shift+Enter 换行，中文输入法组合态不会误发送。
- 后端 SQLite 保存逐阶段事件与时间戳；前端轮询显示真实队列、问题上下文整理、工具执行、检索、重排、生成/核验、卡片整理的阶段时长和总时长。阶段以实际执行为准，未发生的阶段不会伪造。生成和原文核验目前合并显示，不展示模型私有推理过程。
- 短期记忆：sessionStorage 保存本标签页的聊天记录，发送最近8条消息（最多4轮，每条最多1500字）给问题整理器；页面刷新可恢复，新对话清除上下文。最多保留20轮可见历史。
- 长期记忆：用户明确保存的偏好，localStorage 持久保存，最多12条、每条200字；支持编辑、删除和清空，跨新对话保留。没有账号同步，也不自动提取偏好。上下文和偏好会发送到本地服务及配置的 DeepSeek 模型。
- 上下文整理使用 DeepSeek Flash，把指代与偏好整理成可检索的独立问题；偏好不是菜谱证据，菜谱回答仍通过原有工具和原文校验。当前问题优先于旧偏好，可展开查看本次整理后的问题。
- 菜谱卡片显示菜名、原料表覆盖率、已有/待备/可选食材，以及原文和图片入口；真实图片由已有图片工具返回，不用虚构配图。普通问答按实际来源显示卡片。
- 原文做法改为分标题与步骤展示；所有文本经 textContent 输出，来源与图片保留原有白名单接口。
- 手机和桌面响应式布局，窄屏默认收起长期记忆。

## 验证与限制

自动化296项测试通过（原291项加5项记忆与阶段事件测试）；JS语法检查通过。浏览器实测：原文菜谱卡片、刷新恢复历史、保存偏好后刷新保留、新对话清空短期上下文、偏好删除、连续追问展开为“蒸水蛋还需要什么调料？我的口味偏好是清淡。”。

实测时 Milvus 容器已停止；启动后再次退出（exit134），完整向量问答本次返回经过核对的原文候选降级结果。这是目前完整 RAG 在线验收的限制；前端没有把候选原文伪装成已核验答案。原文、图片和简单原料表推荐可本地工作，DeepSeek 上下文整理已真实调用成功。本轮未修改向量集合或容器数据。

阶段耗时包含相邻进度事件间等待及工作时间，不能等同于纯模型推理时间。用户保存的偏好通过检索问题影响回答，不能替代完整过敏原或饮食安全检查。
