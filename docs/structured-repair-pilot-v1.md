# 两篇结构化草稿的独立修订与隔离对照

2026-10-12。依据[离线复评](structured-offline-audit-v1.md)的缺项和误判，针对可乐鸡翅、蒸水蛋分别生成**独立的助手修订候选**。原有 `extraction_pilot/.../recipe.json` 保留为模型草稿；修订文件在 [`data/structured/repaired_pilot/`](../data/structured/repaired_pilot/)，记录原草稿路径和 SHA-256。没有调用模型、修改 Milvus 或接入正式回答。

| 菜谱 | 本批修订 | 来源核对结果 |
|---|---|---|
| 可乐鸡翅 | 删除无依据的生姜数量冲突；保留计算生抽15克与操作约10克＋3克的实际差异；补“剩余姜片”、小葱挽结和新鲜鸡翅条件分支；去除盐重复观察 | 19实体、40观察，逐字引用及扩展边界均通过 |
| 蒸水蛋 | 分开记录原料/计算热水与操作20~30度温水、锅中约3cm深水；补步骤加盐、盘子和蛋液引用；把“锡纸或保鲜膜”和“锡纸或盘子”保留为不同章节的替代关系；删除三个可选佐料被错误捆成“至少一个”的关系 | 13实体、24观察，逐字引用及扩展边界均通过 |

“鸡蛋”没有被设成“新鲜鸡蛋”的库存别名：原文要求新鲜，用户仅报告鸡蛋时仍需确认。水的原文称呼虽在同一条目下关联，蛋液用量、温度和蒸锅用水以不同观察及差异保留，不能合算。两份修订的 `activation.enabled=false`、`answer_policy=null`；结构与边界通过只是针对性修订的验证，不是用户批准或全字段语义验收。

另外运行了4组[隔离库存对照](../data/evaluation/structured-repaired-isolated-v1.json)。它只比较明确名称，不生成“可以直接制作”结论：

- 可乐鸡翅：库存含啤酒时，“料酒或啤酒”替代组按名称匹配；两者都未列出时，该组标为 `not_listed`。冷水、油仅在步骤中出现，单独列为步骤用料。
- 蒸水蛋：库存只有“鸡蛋、热水、盐”时，新鲜鸡蛋仍为 `not_listed`；即便写明“新鲜鸡蛋、温水、盐”，温度、数量、工具及原文差异仍未评估。

复现：

```sh
python3 scripts/curate_structured_drafts.py
python3 scripts/evaluate_repaired_recipes.py
python3 -m unittest discover -s tests
```

项目170项测试通过。修订候选会在使用前复核当前菜谱原文和原模型草稿哈希；原文件变化则拒绝旧数据。当前正式RAG与Agent仍使用原有安全路径。下一批若要扩大结构化覆盖，需要先为另外三篇无有效草稿的菜谱建立可检查数据，再验证数量、可选条件和工具准备的完整回答，不宜仅凭本批四个名称对照启用自动推荐。
