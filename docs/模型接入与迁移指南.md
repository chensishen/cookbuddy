# 本项目模型接入与迁移指南

核对日期：2026-10-27。用途：把本项目使用的模型接入另一个项目。配置以本次读取的本地有效配置和代码为准；历史文档中的旧模型不等于当前线上配置。本文不含密钥，不更改现有服务。

## 1. 全部模型清单

| 用途/状态 | 请求中的精确模型ID | 当前接入地址 | 密钥配置 | 说明 |
|---|---|---|---|---|
| 当前聊天、意图理解、Agent、来源复核、记忆提取、摘要与改写 | `workbuddy-ai/deepseek-v4.1-flash` | `http://127.0.0.1:3425/v1` | `LLM_API_KEY` | 本机代理的路由别名；不是所有供应商通用的模型名 |
| 当前知识库与记忆向量化、语义匹配、评测向量 | `Qwen/Qwen3-VL-Embedding-8B` | `https://api.siliconflow.cn/v1` | `EMBEDDING_API_KEY` | 实际使用文本输入、1024维float向量 |
| 当前检索与记忆重排 | `Qwen/Qwen3-Reranker-8B` | 同上 | 同上 | 文本重排；不是带VL的同名家族成员 |
| 配置中的独立评测裁判 | `Qwen/Qwen3.5-35B-A3B` | 当前继承聊天代理地址 | 当前继承聊天密钥 | 非正常用户问答必需；当前代理是否支持此模型尚未验证 |
| 可选离线菜谱结构化抽取工具 | `Qwen/Qwen3-32B` | `EMBEDDING_BASE_URL`，当前为硅基流动 | `EMBEDDING_API_KEY` | `extract_recipe_pilot.py`的默认抽取模型，不是当前聊天模型 |
| 同一离线工具的复核；历史聊天模型 | `Qwen/Qwen3-8B` | 同上 | 同上 | 默认复核；CLI可交换8B与32B的角色 |

当前正常聊天链路需要前三项；评测再加裁判，离线结构化抽取再加32B/8B。意图、摘要、记忆并没有分别部署一套专属模型。没有另行接入语音识别、语音合成、文生图或独立OCR模型；展示菜谱图片使用本地文件与章节索引，不能据此认为已实现视觉熟度判断。

## 2. 模型本身与项目用法的区别

官方模型卡与供应商接口于本次核对时查阅；以下原生能力不保证由当前代理或账号完整开放。

| 模型 | 官方信息 | 本项目实际用法 |
|---|---|---|
| DeepSeek-V4.1-Flash | 参见官方模型卡[S1]；官方权重MIT许可 | 通过本机路由别名调用文本对话、JSON与工具链；未核实代理后端快照、原生上下文上限、视觉输入及最大输出额度 |
| Qwen3-VL-Embedding-8B | 8B；多模态Embedding；32K上下文；支持64～4096维；Apache-2.0 [S2] | 纯文本1024维；文档正文中的图片只保留Markdown引用，没有把实际图片像素送入Embedding |
| Qwen3-Reranker-8B | 8B文本重排；32K上下文；Apache-2.0 [S3] | 问题+候选文本→相关性分数；按分数排序 |
| Qwen3.5-35B-A3B | 官方卡原生上下文262144，可扩展；Apache-2.0 [S4] | 文本评审/JSON评分，不用于给用户选菜；供应商实际窗口、额度另外确认 |
| Qwen3-32B / Qwen3-8B | 官方模型卡见[S5][S6] | 离线抽取与复核；不应因旧记录而替换当前聊天配置 |

模型卡许可与所用API服务条款是不同事项。本文没有测量自部署GPU显存、吞吐或量化效果，不能把模型名称中的参数规模换算成已验证的硬件需求。

## 3. 地址、鉴权、输入输出

统一使用JSON POST，请求头：

```http
Authorization: Bearer <该服务自己的密钥>
Content-Type: application/json
```

`base_url`已包含`/v1`，只追加下面的路径，避免写成`/v1/v1/...`。API通用字段依据硅基流动文档[S7][S8][S9]，具体项目取值依据本地代码。

### 聊天、JSON与工具调用

- 路径：`/chat/completions`。
- 输入：`model`、`messages`；每条消息含`role`和`content`。
- 常规文本输出：`choices[0].message.content`。
- 结构化输出：请求`response_format: {"type":"json_object"}`；返回内容仍需JSON解析、字段类型与业务约束校验。提示词中明确要求JSON。
- 工具输出：`choices[0].message.tool_calls`；执行白名单工具后，以`role=tool`及相应`tool_call_id`返回，再继续对话。不要把工具调用当成最终用户答案。
- 同时读取`finish_reason`和可选`usage`；`length`是截断，不能直接把不完整JSON当成功。
- 本项目既有非流式调用，也有LangChain/SSE页面；网页SSE不等于所有底层模型请求都在流式传输。

最小请求体：

```json
{
  "model": "workbuddy-ai/deepseek-v4.1-flash",
  "messages": [
    {"role": "system", "content": "用中文回答，返回JSON对象，字段为answer。"},
    {"role": "user", "content": "简单介绍你能做什么。"}
  ],
  "temperature": 0,
  "max_tokens": 700,
  "stream": false,
  "response_format": {"type": "json_object"}
}
```

### Embedding

- 路径：`/embeddings`。
- 输入：`model`、`input`、`dimensions=1024`、`encoding_format=float`。
- 输出：`data[i].embedding`及`data[i].index`；批量时按index还原输入顺序。
- 本项目记忆/意图调用会截取`text[:6000]`：这是字符截取，不是模型的6000 token限制。正式菜谱分块采用768 token代理上限，以`cl100k_base`估算，不是模型原生tokenizer上限。
- 返回值应校验：维度恰好1024、每项为有限数值、向量不全零。更换供应商时也要验证，而不是假设支持同一`dimensions`参数。

```json
{
  "model": "Qwen/Qwen3-VL-Embedding-8B",
  "input": "查询：如何制作牛奶面包的酵头？",
  "dimensions": 1024,
  "encoding_format": "float"
}
```

### Reranker

- 路径：`/rerank`；不是聊天接口，也不是Embedding接口。
- 输入：`model`、`query`、`documents`字符串数组、`top_n`、`return_documents=false`。
- 输出：`results`数组，元素含`index`与`relevance_score`。`index`指向原候选数组；勿按返回位置去取原文。
- 重排分数不是概率，也不能直接与COSINE距离/分数混用。
- 当前模型名在多处写死；并没有全项目通用的`RERANK_MODEL`配置项。下方迁移模板的该变量是给新项目使用的，复制回本项目不会自动生效。

```json
{
  "model": "Qwen/Qwen3-Reranker-8B",
  "query": "酵头如何发酵？",
  "documents": ["把干酵母与温水混合。", "烤箱预热后放入面团。"],
  "top_n": 2,
  "return_documents": false
}
```

## 4. 本项目真实参数与预算

这些是应用设定，不是供应商承诺；父任务剩余时间、排队和限流可能让调用提前结束。

| 调用位置 | 温度/输出参数 | 超时与重试 |
|---|---|---|
| Hybrid Intent Router | temperature=0，max_tokens=650，JSON | `config/nlu.yaml`：5秒；实际单次请求attempts=1 |
| 在线Agent模型工厂 | temperature=0.2，抽取模式0；max_completion_tokens=700 | 单次20秒，连接5秒，SDK重试0；服务层按配置最多3次尝试 |
| 普通来源问答生成 | temperature=0.2，max_tokens=2500；紧凑完整菜谱4096，常规JSON | 底层生成45秒、复核90秒；还受阶段/任务预算限制 |
| 来源复核 | max_tokens=2048 | 默认非思考；可按已有环境开关启用思考预算1024 |
| 记忆通用JSON调用 | temperature=0，默认1200；提取1800；摘要400 | 总预算40秒；截断时可扩一次输出预算，上限8192 |
| 会话改写旧辅助入口 | temperature=0，max_tokens=900，JSON | 45秒 |
| 记忆Embedding/重排 | Embedding1024维；重排top_n=全部候选 | timeout=30秒、attempts=2，受父预算限制 |
| 菜谱独立重排脚本 | 默认最多10候选，选前5 | timeout=8秒、attempts=1；在线编排重排另设2秒预算 |
| Ragas裁判 | temperature=0，max_tokens=8192 | SDK timeout=90秒、SDK重试0；评测框架另有有界重试与指标180秒限制 |
| 离线结构化抽取 | temperature=0.6、top_p=0.95；默认max_tokens=5000；复核1000 | stream=true，enable_thinking=true，thinking_budget=256；网络60秒，单次输出总时长最多240秒，最多3轮网络尝试 |

Agent当前整次请求预算30秒，最多8次模型调用、5次工具调用。短期记忆窗口6轮、Agent窗口预算4000 token；这些不等于模型上下文容量。底层通用治理的默认并发2、RPM60、TPM60000是项目本地限额，可用`RECIPE_MODEL_CONCURRENCY`、`RECIPE_MODEL_RPM`、`RECIPE_MODEL_TPM`覆盖，不能据此认定账号拥有相同额度。

离线抽取输出先做JSON/原文引用/语义复核，再决定是否进入后续流程；它不是一个调用就能保证正确的数据库导入器。

历史/备用配置只作为迁移参考：

- `RECIPE_GENERATION_FALLBACK`可指定同一服务上的备用模型名；不能只填另一个供应商的模型名就跨供应商切换。目前是否设置该变量需部署时另查，本文不假定已启用。

## 7. 不依赖本项目的最小Python调用示例

仅用Python标准库。先将所需配置设置为进程环境变量；Python不会自动读取`.env`。下面函数按需调用，不会自动发起付费请求，不包含cookbuddy业务和数据库依赖。

```python
import json
import os
from urllib.request import Request, urlopen
from urllib.parse import urlparse


def post(base, key, route, body, timeout=30):
    req = Request(base.rstrip('/') + route,
                  data=json.dumps(body, ensure_ascii=False).encode('utf-8'),
                  headers={'Authorization': 'Bearer ' + key,
                           'Content-Type': 'application/json'}, method='POST')
    with urlopen(req, timeout=timeout) as response:
        return json.load(response)


def chat(question, *, judge=False):
    prefix = 'EVAL_JUDGE' if judge else 'LLM'
    base = os.environ[prefix + '_BASE_URL']
    body = {
        'model': os.environ[prefix + '_MODEL'],
        'messages': [
            {'role': 'system', 'content': '用中文简洁回答。'},
            {'role': 'user', 'content': question},
        ],
        'temperature': 0 if judge else 0.2,
        'max_tokens': 700,
        'stream': False,
    }
    if urlparse(base).hostname == 'api.siliconflow.cn':
        body['enable_thinking'] = False
    elif urlparse(base).hostname == 'api.deepseek.com':
        body['thinking'] = {'type': 'disabled'}
    result = post(base, os.environ[prefix + '_API_KEY'],
                  '/chat/completions', body)
    choice = result['choices'][0]
    if choice['finish_reason'] != 'stop':
        raise ValueError('模型未完整结束；检查截断或工具调用')
    return choice['message']['content']


def embed(text):
    dimensions = int(os.environ.get('EMBEDDING_DIMENSIONS', '1024'))
    result = post(os.environ['EMBEDDING_BASE_URL'],
                  os.environ['EMBEDDING_API_KEY'], '/embeddings', {
        'model': os.environ['EMBEDDING_MODEL'], 'input': text,
        'dimensions': dimensions, 'encoding_format': 'float',
    })
    vector = result['data'][0]['embedding']
    if len(vector) != dimensions:
        raise ValueError('返回维度与配置不符')
    return vector


def rerank(query, documents):
    if not documents:
        return []
    result = post(os.environ.get('RERANK_BASE_URL',
                                 os.environ['EMBEDDING_BASE_URL']),
                  os.environ['EMBEDDING_API_KEY'], '/rerank', {
        'model': os.environ.get('RERANK_MODEL', 'Qwen/Qwen3-Reranker-8B'),
        'query': query, 'documents': documents, 'top_n': len(documents),
        'return_documents': False,
    })
    return [
        {'text': documents[item['index']], 'score': item['relevance_score']}
        for item in sorted(result['results'],
                           key=lambda item: item['relevance_score'], reverse=True)
    ]

# 按需取消注释；这些调用会访问对应服务并可能计费。
# print(chat('你好'))
# print(len(embed('一段需要检索的文本')))
# print(rerank('如何发酵', ['烤箱预热', '酵母与温水混合']))
# print(chat('请按明确的评分标准评审这段答案：……', judge=True))
```

这是最小协议示例，不是生产级客户端。上线复用时补足业务schema校验、有界超时与重试、并发治理、密钥加载与脱敏日志；避免SDK和业务层同时重试造成请求倍增。裁判的正式提示词和评分规则需单独迁移，仅调用裁判模型并不等于完成评测。

## 8. 向量库迁移的兼容要求

本次活动库：`recipe_bounded_v4_metadata`；元数据路径`data/processed/recipe_versions/bounded_v4_metadata/embedding-metadata.json`。该值优先于README里的历史集合名。

- 模型：`Qwen/Qwen3-VL-Embedding-8B`，供应商硅基流动，1024维。
- 文档输入：菜名、章节、原文路径 + Markdown正文；`path_in_embedding=true`。共2074块。
- 当前说明中的768 token是分块代理上限，tokenizer代理为`cl100k_base`。
- 查询向量与文档向量必须来自兼容空间；仅仅维度同为1024不能证明不同模型、模板或供应商实现可混用。
- 换Embedding模型、维度、实际文本拼接/指令策略时，重建受影响向量、版本化切换；不要覆盖后混查旧向量。
- 更换聊天或裁判模型不会自动要求重建Embedding库。
- 更换重排模型通常不改变已有向量，但需要重新验证排序质量和分数阈值。
- 仅调用模型不要求Milvus/PostgreSQL/Docker；这些是本项目的检索、记忆与持久化配套设施。

## 9. 价格、额度、可用性与迁移验收

本次做配置与代码审计，没有重新请求所有模型做可用性/计费测试。不能把“已填写密钥”写成“接口可用”。

| 项目 | 本次能够确认的范围 |
|---|---|
| API密钥 | 本地已配置；实际值不导出。新项目应通过本机安全配置或密钥管理器另行注入 |
| 单价 | 未从账户计费控制台核验，不提供可能过期的每百万token报价 |
| RPM/TPM、并发、上下文及最大输出 | 项目本地预算见第4节；账号/代理实际上限未验证 |
| 本机代理后端 | 已知路由ID与地址；未证明某个固定权重快照、上游供应商或实际计费方案 |
| 余额/有效期/商用服务权限 | 未验证 |
| 历史服务故障 | 项目测试曾出现代理502与生成超时，历史成功不代表本次接口实时正常 |

新项目接入顺序：

1. 列模型：在所用服务允许时以鉴权`GET /models`核对ID；列表存在仍不代替实际请求。[S10]
2. 聊天：一次普通文本、一次JSON对象、一次工具调用，分别验证返回字段与截断行为；需要流式时另测SSE。
3. Embedding：同一输入重复请求，校验长度、有限数值与非零；单条/批量分别测，确保index映射一致。
4. Rerank：至少两条语义明显不同的文档，核对index、候选数量、分数类型、相关性排序。
5. 裁判：显式独立地址/模型/密钥，给定答案、参考资料和评分规则；不把生成器自评当独立评测。
6. 用少量目标项目的真实数据验证质量、P50/P95延迟与实际账单，再确定正式预算。失败保留HTTP状态、阶段、耗时、请求ID，不记录Authorization。
