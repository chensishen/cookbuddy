## 原因与改动

| 原因 | 修复 |
|---|---|
| 生成脚本、旧Agent及旧多Agent入口重复拒绝HTTP | 统一委托require_llm校验，继续只允许HTTPS及本机HTTP，不允许外部明文地址 |
| 降级来源只有line_range，导出器强读line | 兼容行号与行号范围；导出失败单独标记record_export_error，不能覆盖已生成答案与已持久化会话 |
| “说明还缺什么”进入extra_constraints并污染后续轮次 | 增加missing_ingredients回答字段；旧状态只迁移完全识别的输出要求，未知饮食约束继续保留 |
| 自然记忆查询未命中管理入口 | “我不吃什么”“我喜欢吃什么菜”等进入已有、按当前用户隔离的画像读取，不调用菜谱生成 |
| 整餐澄清被当作未知要求 | 识别明确允许常备调料、无需核实价格的语句；预算金额、未知限制和否定允许仍拒绝假核实 |
| 普通新手做法绕过已有来源直答 | 完整识别该句式后复用逐字核对的原料、计算及操作流程；额外替代或限制仍走QA |
| 模型没有调用工具即结束 | 在无任何工具证据时补一次检索；不展示模型未经核实的自由回答 |
| 一次生成失败抹掉其他成功工具 | 只为失败条目生成候选回退，保留其他已核实原文、图片或不足结论 |
| 原文被再次截到4000字符 | 移除展示层重复截断；明确完整原文/图片走受约束直达分支，额外要求不能被快速路径吞掉 |
| 候选片段重复、指定菜谱混入别菜 | 摘录按来源与章节匹配并去重；指定菜谱的搜索以服务端确认的来源过滤 |
| 前端不识别LangChain工具名 | 合并同一来源的search_recipes/get_recipe_detail/source_fact与图片结果，优先已验证答案；原文沿用逐行插图展示 |
| 整餐入口承诺不具备的预算能力 | 模板改为人数、时间、菜汤数量；明确预算要求仍说明无法核实，不编造采购价格 |
