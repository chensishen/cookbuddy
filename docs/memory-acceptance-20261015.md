# 记忆机制测试与改进 · 2026-10-15

## 复现与修复

本轮使用独立生成的测试用户，不更改现有用户画像；数据库集成测试清理自己创建的数据。

| 场景 | 修复前结果 | 修复后行为 |
|---|---|---|
| 两条口味更新，旧提取任务最后完成 | 较旧的“清淡”覆盖较新的“微辣” | PostgreSQL 用户消息 ID 决定画像更新顺序，在用户锁事务内拒绝旧版本写入 |
| 记忆上下文长度限制 | 标称3500，完整 JSON 实际9670字符 | 将内容、ID、版本及来源元数据一起计入3500字符上限；保留完整事实，放不下则跳过，不截断事实 |
| 相同内容的过期记忆再次确认 | 被当成无变化，仍无法召回 | 重新设置有效期、递增版本并写入向量同步 Outbox |
| 用户遗忘与任务压缩交错 | 压缩写入没有检查遗忘代次，存在恢复摘要风险 | 压缩捕获 memory_epoch 并在写入时校验；已遗忘时放弃摘要及后续压缩处理 |

上下文只保留注入所需来源字段，完整逐字证据仍在数据库；3500限制是记忆 JSON 的字符数，不是整个 Prompt 的 token 数。画像顺序保护依据服务端消息序号，不采用模型时间或客户端时间；旧记录没有该序号时仍兼容，新的正常对话提取会写入序号。
