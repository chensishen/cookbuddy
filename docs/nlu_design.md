# 意图理解与容错重构

2026-10-26。任务来源：用户提供的《AGENT_SPEC_意图理解与容错修复》。规则处置见 [gate_inventory.md](gate_inventory.md)，可执行评测见 `eval/nlu/evaluate.py`。

## 分工与入口

默认网页与 SSE 共用 `ChatEngine`。`prepare` 在认证、输入长度检查后读取当前用户允许使用的短期上下文，执行 `src/nlu/router.py:understand`，之后才推进任务状态和执行工具。经典 `--legacy` 入口也使用同一理解器。没有配置的直接 `prepare` 单元测试使用离线兜底；线上服务总是传入受信配置并启用真实模型。

理解器只输出意图与槽位；不输出配方事实、来源权限或记忆修改授权。身份/能力、闲聊、库外请求、澄清都有显式响应分支。通用对话即使关闭直接执行或 Agent，也不会补做菜谱检索。已判定菜谱任务才允许工具规划与来源兜底。

原句始终留在会话和执行输入中，规范化结果作为理解输入。上下文限于摘要、槽位、最近两轮；M0 不读取旧上下文，M1 不读取持久槽位或摘要，禁用记忆时不恢复旧槽位。记忆提取、授权、确认、RLS、过敏/忌口过滤和最终证据检查继续由原模块负责。

## 规范化和名称匹配

`normalize.py` 执行 NFKC、繁转简（可关）、标点与空白归一、末尾表情清理。只在已经完成的序数或独立句尾后识别孤立数字，原文仍交给模型。数量、温度、时间和第 N 道内部的数字不删除；存在冲突的旧数量输入仍进入澄清。

`matching.py` 提供精确、规范化、包含、编辑距离、拼音、向量和模型候选消歧的层级。填充词只用于名称清洗。`rapidfuzz` / `pypinyin` / `opencc-python-reimplemented` 的版本已写入运行依赖及锁文件。菜名沿用原有别名映射，再做模糊匹配；不能把食材原料表中的未知名称直接改成猜测的名称。

章节候选来自当前菜谱的元数据；完整层级路径和父章节仍可选取其后代，分块原文不合并到其他来源。原文和图片查询使用同一章节匹配结果，图片哈希、引用行与来源版本校验保持执行。

阈值位于 `config/nlu.yaml`：高分 0.88、中分 0.65、差距 0.08。同分且影响结果的候选须选项澄清；低分明确提示未找到并给候选；模糊命中显示理解说明。向量升级复用现有 embedding，只在模型/名称结果不足时调用；模型同义选择和消歧与本轮理解合并，避免独立的第二轮 query 改写。

## 模型、缓存和失败处理

模型由 `router.model` 指定；空值复用当前供应商配置，不新增密钥。温度为 0，结构化 JSON 经 schema、枚举、计数、菜名/章节/食材目录和引用范围校验。每次预算 3 秒，失败至多重试一次。prepare 总预算调整为 12 秒以容纳重试及必要的名称升级，仍受整轮 30 秒上限约束。失败、低置信或非法 schema 使用规则兜底；最终未知给友好回复。规则是后置兜底和校验，不是入口拒绝条件。

缓存 TTL 300 秒；key 为规范化文本、上下文（含用户/会话隔离）、配置、提示版本的哈希。缓存不使用原文键；缓存不可用不阻断理解。不同用户、不同上下文和提示变更不会共享结果。缓存中的旧辅助噪声不应被当成新的执行限制。

运行 trace 只记录固定意图、置信度、匹配层级/分数、路径、错误码、耗时和用量。异常正文、用户问题、槽位原文、候选名称和自由模型文本不进入 trace。会话数据库是已有用户内容存储，不属于运行日志。

## 条件与状态的兼容

`adapter.py` 把结构化槽位转换成原有 reducer 的 Edit。原句中已识别的条件与输出字段继续保留，模型不能擦除它们；已完整解析的推荐不为可选食材追问；有明确原文答案的命名菜谱问题不被模型臆造的章节歧义卡住；旧状态先执行已有版本归一，避免旧输出要求污染推荐条件。更新携带 Edit 元数据，且本轮没有明确修改时不把模型复制的上轮口味当作新要求，使显式口味和记忆派生口味不会互相覆盖。

序号只对本会话的推荐列表取值，超出范围说明已有数量并给选项。排除列表贯穿准备、直接执行、工具和经典入口；菜名、来源路径不由模型生成。整餐规划的已解析人数、时间和菜汤结构继续交给原规划器。

未知条件返回一条澄清及选项，推荐器不会再返回 `None`。用户可以明确选择先按已理解条件推荐；这个选择只移除未识别的临时请求片段，不改变独立保存的硬约束。条件不能被模型当成噪声悄悄删除。硬约束解除、删除记忆仍由原授权/确认链路裁决。

澄清最多一个问题、2–4 个按钮，两种页面均支持点击。名称澄清的待选项存于当前会话；重复的低风险名称歧义可以透明采用最可能项，避免循环追问；这不适用于放宽限制或删除记忆。

## 验证与范围

- 三个截图问题先写成红测试；基线失败输出保留在 `eval/nlu/baseline-regressions.txt`。
- `nlu_robust_v1.jsonl` 包含 168 条：42 条基础样例和固定种子的扰动。包含口语、同音字、删字、空格、全半角、繁简、尾数和表情。
- 最初夹具/报告保留为 `.initial` / `baseline-initial.json`；最终夹具根据真实目录把无唯一配方的“红烧肉”标为合法澄清，并扩充扰动。最终基线用重构前原文工具快照重新计算，记录快照 SHA256。它是组件基线，不冒充旧系统端到端准确率。
- 扰动稳定性比较意图、任务相关槽位和回答模式；`raw_noise` 等辅助字段不计作业务槽位变化。
- 实时模型报告、缓存报告、规则离线报告分别保存；缓存耗时不能代替首次模型延迟。报告提供路径分布和实际 token 计数，不预填价格或用量。
- 检索开发集每阶段对照；另对 6 份来源逐字证据和引用元数据做前后比较。规则引用准确率与语义引用支持率分别说明，不把前者宣称为后者。
- 所有已有后端/前端测试和实际数据库、向量服务集成检查用于检验兼容；具体命令和结果以本轮验收报告为准。

## 已知边界

当前供应商模型一次首次理解约需秒级；没有用缓存命中结果宣称达到了 P95 增量 500ms。要认证这一门槛，需要与同负载旧系统做足够规模的端到端对照，或配置经过验证的更快理解模型。本轮的小样本和单机测试不认证生产 SLA。

名称候选和已有约束执行器仍限定于当前知识库。无法核实的新要求会透明澄清；不会为追求“总能回答”而解除过敏、替换原料或猜配方。完整语义引用准确率仍需独立评审；本轮来源核对不替代它。
