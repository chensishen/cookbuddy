# 推荐筛选与卡片内容修复（2026-10-16）

## 本次范围

针对用户截图中的两句原话：

- 我喜欢吃辣的，给我推荐几道菜
- 我有鸡肉给我推荐几道，辣的

上一版将出现辣味配料等同于优质辣菜推荐，并将“我有鸡肉”重新送入全配料库存核对；卡片也只有一句匹配依据，缺少菜品介绍和推荐理由。

## 修改

- 推荐入口支持“推荐几道，辣的”以及食材、口味换序等表达，省略“菜”字仍识别推荐意图。
- 明确库存声明也可以先选菜，只有请求“还缺什么、够不够、只有”等完整库存判断时，才回到原 RAG/库存校验路径。推荐不再因缺少完整配料清单而整份被拒绝，也不声明用户配料已经备齐。
- 默认“几道菜”候选限制在水产、荤菜、素菜、汤羹类别，排除调料酱汁、早餐、主食、饮料与甜品。明确请求其他类别时保留原始要求交给原流程，不扩大简单筛选器的能力声明。
- 按明确辣味介绍与配方实际辣味材料的匹配强度排序，同质量候选再考虑多样性，最终以来源路径作稳定次序。可选加辣不能挤掉更强的直接匹配；必要时才作为带明确提醒的备选。计算章节不能将原料表标注“可选”的同种辣味材料升级为必需。
- 每张卡片增加 `description`、`reason`、`main_ingredients` 和必要的 `notice`。介绍取对应简介中的完整原句，仅移除 Markdown 格式；没有合适简介时使用原料表构造有限介绍。推荐理由结合本次食材与口味，以原文风味词和配料解释为什么适合，不再只是“原文用到某配料”。每项展示仍保留对应逐字原文和真实行号。
- 纵向卡片取代三列窄卡片；桌面图文并排，手机图片置于文字下方。推荐理由使用 15px，主要用料 14px，避免旧样式将它们压到 12px。没有图片时不预留空白图片框。
