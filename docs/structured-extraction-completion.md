实现了五篇自动抽取试验：原文编号 → 模型抽取 → 程序定位原文 → 格式与引用校验 → 预先设定的边界检查 → 独立模型复核 → 保存草稿和失败记录。输出截断、非法JSON、伪造数量、无依据别名、工具混入采购项等不能被算作检查通过。限流有限重试，失败后保存可恢复记录；新草稿不会继承旧版复核意见。

60项测试通过，包括来源变化、越界路径、伪造引用、替代关系、多章节数量、接口不可用及复核版本隔离。结果见[最终数据检查](../data/structured/structured-extraction-audit.json)。

## 为什么采用这些处理方式

- 按章节保存观察：原料表可能漏掉步骤用料，可选项可能只在某个做法出现，不能压缩成一个全局“必需”标签。
- 原文由程序填入：模型只提供定位片段，避免让模型自行编造路径、摘录和行号；数量需要与原文条目直接关联。
- 使用预设边界与模型复核：引用存在不等于解释正确，温水、工具、可选佐料等需要另行检查；模型自评不能独自决定通过。
- 尝试32B抽取、8B复核：此前8B试验出现遗漏和错类，因此比较较大抽取模型的表现；目前结果尚不足以证明32B更可靠。正式回答生成仍保持用户指定的Qwen/Qwen3-8B。
- 自动草稿单独存放：抽取质量不稳定时，可以继续诊断和重放而不影响已接入的三个样本回答。

## 本轮范围与后续入口

本轮完成了统一格式、自动抽取工作流、真实小批量试验和失败隔离；五篇的语义通过目标仍未达到。已在有限重试后保留失败，不继续无界请求接口。下一步研究应先核实接口限流条件，并对照原文整理少量参考标注，评估抽取与复核的实际错误，再决定是否扩大批次。

本轮没有改写Milvus、重新Embedding或处理图片。图片仍保留在原文及已有图片清单中，没有OCR、图像描述或图片向量。具体字段、运行命令和限制见[操作说明](structured-extraction.md)。
