# 真人测试反馈修复（2026-10-23）

范围：回答更亲和、推荐有具体理由；修复“第二道→换一道→这道缺什么”和“完整原文→只看酵头图片→酵头具体事实→烘烤具体事实”两组连续任务。保留历史错误回答及中间失败证据，不改写旧会话内容。

## 原因与修改

1. “第二道怎么做？请给我用料和完整步骤。”没有被识别为序号追问，导致选菜任务关闭；现在整句识别并保留原列表。
2. “不要刚才第二道”曾被当成食材忌口或无法处理的额外条件。现在从原列表解析排除对象，单道换菜保留库存并排除已推荐菜，不写成食材偏好。
3. “这道还需要准备哪些食材”现在绑定当前选中菜或唯一候选，按原料表对照已声明库存；不能唯一定位时先询问菜名。
4. 省略完整菜名的图片、用量、温度追问缺少稳定的来源绑定。现在继承当前菜谱身份，保留本轮原问题，针对性事实查询限定同一来源。
5. 更深的持久化问题：prepare 已处理话题边界，persist 又重复清空槽位，抹掉了本轮刚选中的菜谱。现在边界只在准备阶段执行一次；新增真实 PostgreSQL 跨轮回归测试。
6. 图片工具附带的上下文原文曾直接进入正文。现在图片请求使用 images_only 展示，相关文字保留在依据中；流式事实回答优先显示简短答案，不重复展开整段审计摘录。
7. 库存推荐每道菜均提供基于原料表匹配的推荐理由，主页面和流式页面同步显示。推荐、补料回答更自然；生成提示要求亲和表达，仍不得补写无依据的功效、保证或推荐理由。
