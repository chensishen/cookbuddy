# 小规模菜谱问答测试

目前使用两份测试菜谱、13 个按 Markdown 副标题划分的文本块。

流程：问题 → Embedding → Milvus 检索前三个候选 → Rerank → 回答生成。

| 步骤 | 模型或设置 |
|---|---|
| Embedding | Qwen/Qwen3-VL-Embedding-8B，1024 维 |
| 向量检索 | recipe_test_v1，COSINE，Top K = 3 |
| 重排 | Qwen/Qwen3-Reranker-8B |
| 回答生成 | Qwen/Qwen3-8B，关闭思考模式 |
| 依据覆盖核对 | Qwen/Qwen3-8B，开启思考，thinking_budget = 1024，单独请求 |

## 如何提问

先确认 Milvus 已启动，本地 `.env` 已配置硅基流动的接口地址与密钥。

在项目目录运行：

```sh
python3 scripts/ask_test_recipes.py "面包外面焦了，里面没熟怎么办？"
```

也可以不带问题运行，按提示输入一个问题：

```sh
python3 scripts/ask_test_recipes.py
```

每次运行只处理一个问题，并保存这次检索、重排、回答及完整流程记录。问答入口也可以通过脚本的绝对路径从其他目录运行。

## 如何看结果

回答固定展示为：简短回答、原文依据、来源。模型为每项结论选择支持它的原文行号，程序提取原文并添加引用编号。选中原料列表单个条目时保留完整连续列表；选中编号步骤时保留章节内的完整编号步骤范围，避免遗漏材料或后续操作。因此原文依据可能较长。来源包含菜名、章节、原文路径与章节行号。

核对调用的思考预算使用[硅基流动接口参数](https://docs.siliconflow.cn/docs/api/chat-completions-post)控制，回答生成仍关闭思考。

完整流程记录保存在 `data/processed/test_dishes/qa-results/`，里面链接本次三个步骤的详细结果。各步骤失败时停止后续操作，已完成的结果仍保留。

自动检查包括引用编号、摘录行号和回答中的部分数值单位是否有原文依据。生成前先根据完整候选资料检查能否回答：资料不足时程序直接说明，不请求生成做法。生成后另一次模型调用仅看选中摘录，核对是否覆盖全部结论。不使用未经验证的固定重排分数阈值。

校验未通过时最多修正一次并再次核对。仍失败时输出“本次未能生成原文依据完整的回答”，与资料不足区分；失败尝试保存在 `answer-results/rejected/`。API 连接失败等情况仍停止流程。JSON 中的 `status` 分别为 `verified`、`insufficient` 或 `validation_failed`；流程运行结束不代表问答通过。

资料不足通常只做一次充分性检查；正常回答通常共三次调用（充分性、生成、依据核对），需要修正时最多共五次，耗时与费用会增加。各次请求与返回保存在生成记录的 `model_calls` 中，原有 `usage` 仅表示最后一次生成调用的用量；未生成回答时表示充分性检查用量。

模型核对仍可能误判，不构成语义正确性的保证。人工查看回答是否直接回答问题、是否遗漏条件、是否混入其他情况的建议，以及资料不足时是否明确说明。知识库规模仍很小，模型给出的有来源回答也需要和原文核对。按份数推导的数值仍可能被现有部分单位逐字检查误拒，这不是本次修复的完整范围。
