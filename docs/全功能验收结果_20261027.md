# cookbuddy 全功能验收记录（2026-10-27）

## 交付与范围

- 可复制的执行总提示词与分组人工清单：`docs/全功能测试提示词.md`。
- 48轮结构化用例：`eval/dialogue/full-function-prompts.json`。
- 真实服务执行器：`scripts/verify_dialogue_functions.py`，按组隔离匿名测试身份，保留组内会话，首次结果不可覆盖。
- 本轮没有修改真实用户的饮食偏好。

这是一套可持续执行的验收，不是“所有功能已完全稳定”的证明。自动集是人工清单的子集，机械断言不替代完整语义判断。报告中的 `semantic_review: pending` 表示该轮仍需完整人工语义复核。

## 已复现并修复

1. 模型理解超时时，“第二道还需要准备哪些食材”错误返回操作原文：保留序号，进入库存与原料对比。
2. 模型漏填序号或沿用旧菜时，明确的“第二项”没有绑定当前列表：按已持久化列表校验、绑定明确序号；越界不猜测。
3. “第一项换一道，第二项保留”被理解成保留条件但没有执行替换：校验两个位置后执行单项替换；同一项同时保留与替换、无效序号要求澄清。
4. “我有哪些饮食偏好”“我还保留了哪些偏好”绕入菜谱流程：通过现有记忆管理路径读取。
5. “忘记香菜偏好，保留微辣”没有正确隔离目标：只处理指定遗忘项；同一项又删又留时不写入。
6. 图片追问后的事实问题继续要求选择章节：具体问答进入现有事实回答路径，不要求可选章节名。
7. 未知菜谱、替代用油和看图判断熟度被误判为非烹饪问题：修正理解提示中的边界，原文与推断仍严格区分。

生产修改：`src/agent/turn_intents.py`、`src/nlu/router.py`、`src/nlu/prompts.py`、`scripts/cookbuddy/ltm/management.py`。回归覆盖位于 `tests/test_dialogue_state.py` 和 `tests/memory/test_management_commands.py`。修复前失败日志与修复后检查日志保存在 `output/full-function-verification-20261027/`。
