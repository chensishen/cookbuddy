## 推荐方案

### 1. 根据问题选择阅读结构

| 问题类型 | 默认展示 |
|---|---|
| 单点问题，例如“要蒸多久” | 先直接回答，再补必要条件；有明确相关配图才显示。不强制铺开整份菜谱。 |
| 完整做法 | 菜名 → 材料及用量 → 分阶段编号步骤 → 必要提醒。将关键温度、时间、判断状态放进对应步骤。 |
| 多菜推荐 | 每道菜独立卡片，先显示匹配理由、缺少材料及关键限制；详细做法按需展开。 |
| 明确索要完整原文 | 保持原文顺序和图片位置，只改善标题、排版和导航，不做内容删减或改写。 |

卡片中仍只显示回答及相关配图；执行过程、原文依据、来源继续放在卡片外的折叠区。没有已核实答案的历史失败记录应使用清晰的失败状态，避免堆叠无对应文字的图片，让图片看起来像答案。

### 2. 使用有来源关联的内容块

让回答生成阶段提供带类型的内容块，例如结论、材料、步骤、提醒，并为步骤携带原文证据编号。图片通过原文来源和行号匹配到内容块，前端只负责排版。新内容结构必须经过现有事实和完整性校验，不能为了好看改变用量或省略条件。

这比前端按关键词、标点或正则猜测标题和步骤位置更可靠。迁移时保留旧回答兼容展示；不尝试用简单分号切割将所有历史长段落自动变成步骤。

在现有答案生成请求中输出内容块，避免为了排版再增加一次模型整理调用，以免再次拖慢回答。

### 3. 控制图文和排版

- 每个步骤先展示动作，再显示时间、温度或完成状态；配图紧随该步骤。无法可靠匹配的图片不强行插入普通问答，明确查图和完整原文请求另按其需求展示。
- 正文建议 16px、行高约 1.75，阅读宽度约 680–720px。用主标题、章节标题、正文和辅助说明形成明确差异。
- 只突出关键数值和限制，避免整段斜体；可选材料说明、背景介绍和故障排查按需展开，但必需材料、不可省略的动作及适用条件默认可见。
- 控制图片高度，保留完整内容和比例，点击再查看大图；避免一张步骤图占据大半个阅读窗口。

### 4. 修正滚动

打开历史时定位到最近一轮问题及答案开头，或恢复用户上次阅读位置。新答案完成后保持答案开头可见；用户已向上滚动时不抢位置。图片加载不应导致文字跳动。长菜谱可提供章节跳转，不另开复杂侧栏。

## 建议实施顺序与验收

先做“回答排版和滚动”：层级、字号、阅读宽度、短回答步骤化的正式输出结构，以及历史打开位置。用单点问题、蒸水蛋、完整面包做法、完整原文各验收一次。

再做“步骤与图片绑定”：以有来源的内容块为基础，验证图片属于同一道菜、同一阶段，条件和图注不丢失。最后改善多菜推荐卡片及长回答导航。

验收应确认：首屏能看到针对问题的答案；操作可逐项阅读；重要用量、时间、温度、条件完整；图片就在相关文字旁；完整原文不删改；Markdown 不裸露；长回答不会自动跳至尾图。

本次只检查了桌面端历史回答及渲染实现。浅色辅助文字存在对比度风险，但尚未测量对比度；未完成手机、键盘焦点和屏幕阅读器测试，不能据此声明无障碍通过。
