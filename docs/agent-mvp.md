# 本地菜谱应用与Agent验收

## 本轮交付

在原有全量文本RAG上增加了三个可调用工具和本地网页入口。可查询做法与已有食材推荐，按菜名查看原文，按菜名、章节或图注查原图。页面同时展示简短回答、逐字依据、来源链接和执行过程。

地址为http://127.0.0.1:8080；启动方式见[README](../README.md)。页面只读取本地知识库清单允许的菜谱与图片，不能读取`.env`或任意系统文件。任务异步执行，界面显示当前阶段；后端一次执行一个任务，最多允许另一个等待任务，避免无界叠加模型请求。

## 三个工具

| 工具 | 实际行为 | 使用边界 |
|---|---|---|
| query_recipes | 复用文本Embedding、Milvus、菜名/食材补召回、Qwen3-Reranker-8B及回答来源校验 | 模型或Milvus不可用时明确失败；不把工具选择当作召回或回答生成 |
| read_recipe | 读取已入库菜谱的真实原文，核对章节版本，按完整行展示 | 查不到唯一菜名或章节时说明不足；长文本明确标记未完整展示 |
| find_recipe_images | 从全量图片来源索引查原图、作者图注和原文位置，核对图片与菜谱哈希 | 最多展示8处引用，保留总数；不把OCR/看图草稿升级为配方事实 |

## Agent如何工作

Qwen/Qwen3-8B接收用户问题与三个工具定义，返回function calling请求。程序检查工具名称与参数，只执行白名单中已有函数，把执行结果通过tool消息交回模型，允许它判断是否需要补充工具。

接口格式参考[硅基流动Function Calling文档](https://docs.siliconflow.cn/docs/userguide/guides/function-calling)。本项目使用显式函数分派，不执行模型返回的代码。最多三轮模型请求、四次实际工具调用；相同参数不重复执行。菜谱RAG工具始终使用用户完整原始问题，防止规划模型遗漏库存或否定条件。

最终展示已有工具的回答与证据，规划模型的自由文字不作为菜谱结论。这保留了原有来源校验与样本规则，也避免再次生成时删掉“可选”“待确认”等限定。当前Agent主要负责工具选择与补充查询，没有宣称已经支持任意自主规划或多轮长期记忆。

直接工具模式不调用规划模型，界面与记录明确区分两种方式。Agent接口失败时，不把直接模式伪装成模型决策；已完成的结果可保留并标为部分完成。

## 实际验证

本轮87项测试通过，包括工具白名单、参数校验、完整问题保留、tool消息关联、重复调用限制、接口失败隔离、原文逐字核对、图片来源、网页文件访问边界及请求来源检查。

真实接口与本地数据验证包括：

- Qwen3-8B自主选择图片工具，为基础牛奶面包酵头问题返回3处图片引用。
- Qwen3-8B自主选择RAG工具，凉拌黄瓜库存比较经向量检索、重排和来源检查完成；回答由原有结构化样本规则生成，不能算作模型生成测试。
- 空气炸锅面包片温度与时长查询实际调用Qwen3-8B回答生成，得到“200°C、5分钟”，引用操作原文，模型覆盖核对通过。
- 不存在的“红烧霸王龙”没有得到做法，返回insufficient和空依据，不借其他菜谱拼造答案。
- 页面原文与图片查询能够提交任务、显示结果、加载原图和来源位置。页面问答验收记录另存于执行记录与测试汇总中。
- 只读查询Milvus实际记录数为2058，未重新写入或更换集合。

上述是小范围功能验收，不是全库准确率评估。[测试汇总](../data/processed/agent-test-report.json)保存本轮真实执行记录路径与状态。

## 仍需逐步改善

全量文本RAG已可运行，但完整数量计算、复杂版本、过敏忌口、任意食材替换、工具充分性仍缺少统一可靠规则。三个结构化样本的已有适用范围继续保留。五篇自动抽取试验没有因本轮页面或Agent完成就被认定为语义通过。

图片当前用于原图与作者图注查询。三张OCR及视觉描述试验仍未启用，尚无全量视觉解析或图片向量检索；照片不能证明内部熟度或具体配方条件。PDF、Word、音视频未出现在菜谱附件目录中，没有伪造支持。

后续重点应是建立人工参考问题与标注，评估召回、重排、引用和缺料判断的实际错误，再改善全库结构化抽取与图片语义解析。当前应用是本地学习MVP，没有公网部署、登录权限或生产运行保证。
