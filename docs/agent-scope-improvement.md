# Agent章节筛选与工具选择修复

## 本轮结果

原基准第26、30题与两道明确筛选的查询，均完成真实Qwen/Qwen3-8B工具调用，助手对照用户请求与原文核对通过，仍待共同审核。144项项目测试通过，本地应用已启动并加载新代码。

| 请求 | 实际执行 |
|---|---|
| 查看宫保鸡丁原图 | 查询全部匹配原图，section为空，返回1处原图引用。 |
| 蒸水蛋原文是否写了成品中心温度 | 保留完整问题调用query_recipes，回答原文未明确写出中心温度，不将20~30温水当作成品温度。 |
| 查看牛奶面包酵头图片 | 保留用户明确提出的酵头关键词，返回3处原图。 |
| 只看蒸水蛋操作章节原文 | 保留操作筛选，使用read_recipe展示该章节。 |

中心温度的缺失判断同时核对完整原文；单独引用操作章节不能证明全篇所有位置都缺少某个属性。

## 修复方式

模型提议调用后、工具执行前增加范围检查。格式合法的本地工具参数中，section不在用户原始问题里时清空，不自动增加成品、操作等范围。用户明确指定且被模型传入的章节或图注关键词保留。

查看原文、查看图片与事实问答分别处理。没有明确查看意图的属性问题使用完整问题的RAG工具，避免把成品中心温度误作成品章节。明确要求图片或原文时，错误的本地工具类型可改成对应工具，而不将这类查看请求强行转为事实问答。

原始模型提议与实际执行分开记录：requested_tool、requested_arguments、tool、arguments、parameter_adjustments。工具反馈同时告诉模型实际执行的工具与修改原因，保持tool_call_id关联。重复调用按实际参数去重。

非法参数或未知工具仍由白名单检查拒绝，不借修改范围隐藏额外字段、错误类型或缺失参数。网页与命令行的直接工具模式不经过模型校正，用户直接填写的section保持原样。

## 为什么这样做

模型此前添加成品筛选，导致真实存在的宫保鸡丁原图查不到；又把中心温度问题交给原文工具读取不存在的章节。这两类错误不能只靠检索排名修复。提示词说明正确做法，执行前检查再守住用户请求范围。

本轮四次真实决策中，模型已直接选择正确工具与参数，没有发生运行时参数改写。强制模型提出错误筛选、错误工具的情况使用测试模型复现，确认程序能够校正并保留记录；不能把单元测试中的纠错计作实际接口中的纠错次数。

## 边界

这是保守的单次请求检查，不是完整语言理解。别名、复杂否定、多个章节或同时要求查看与问答仍未全面验证；不能宣称所有工具选择与筛选均已正确。事实问答仍依赖现有RAG来源与语义检查。

没有变更菜谱原文、向量库、Embedding、生成模型或三工具白名单，没有启用图片描述和自动结构化草稿。
