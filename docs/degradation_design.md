# 降级与餐次菜单修复

实现范围：2026-10-28 用户提供的《降级路径与餐次菜单修复》任务书。根因与原始证据见 `incident_circuit_open.md`。人数、时间、难度仍只保留于会话，不写入长期偏好。

## 配置与实现

- `config/resilience.yaml` 为统一熔断策略；按操作与模型分开，SQLite 事务保证多进程共享。60 秒滚动窗口、最少 3 次、失败率 60%，初次打开 10 秒、退避上限 60 秒、连续两次半开成功后关闭。取消、排队、JSON/schema、4xx 与内部错误不计入依赖熔断。429 使用已有 Retry-After 冷却，单独计数。
- `config/lexicon.yaml` 是餐次同义词的唯一来源，主模型 prompt、备用规则、生成测试共同读取。修改配置后重启进程加载。
- `config/meal_templates.yaml` 根据知识库实际品类定义四餐模板。早餐与夜宵有更短时长和更低难度上限，并排除酒精饮品；午晚餐按人数调整，用户明确菜汤数量优先。未指定餐次时仅在入口读取上海本地时间，并向用户说明推断。
- `scripts/cookbuddy/menu_planner.py` 有界确定性组合，并独立复核硬约束、品类、时间、难度、主料重复与逐字引用。候选不足返回可验证的部分菜单及缺失角色；不放松约束补齐。库存是整餐覆盖率偏好，未要求每道菜含全部库存。
- `src/capabilities.py` 登记全部意图及公开工具。CI 检查登记、每个故障状态和测试格，增加公开工具但缺声明会失败。
- 本地菜单、原文、图片与原料核对不依赖远程向量召回，因此 Milvus、embedding、rerank 不可用时可以继续完成。矩阵中明确记录这些边界没有被调用，不声称模拟了实际远端错误处理。历史召回单独测试实际 embedding 失败。

## 提示与监控

完成胜任的备用路由只记录内部降级状态，不显示故障横幅。精排、工具或理解能力确实受限时说明影响及可执行替代，并带 request_id。两套前端保留执行阶段和耗时。

`/health` 返回六类依赖的状态、失败计数、打开次数/累计时长，以及窗口降级占比和配置告警；不暴露端点、密钥或用户文本。请求占比目前统计经过 worker 持久化的完成请求，不能作为全部入口失败率。告警由健康接口输出供监控采集，不含外部通知服务。

故障状态 `slow` 用超时异常注入，离线耗时只表示代码路径成本，不表示真实模型响应分布。超时选择仍参考根因报告的历史成功请求 P99，并保留失败样本被截断的限制。

## 复现

使用项目指定 Python 3.12 环境，设置 `PYTHONPATH=scripts:.`：

```
python -m pytest tests -q
python eval/degradation/run.py --out /tmp/routes-menus-new.json
python eval/degradation/matrix.py --out /tmp/matrix-new.json
python eval/degradation/live_smoke.py --out /tmp/live-new.json
```

后三个命令拒绝覆盖已有报告。离线路由使用受控主模型 oracle，备用规则、领域归并和本地菜谱工具是真实实现，不等于真实模型自由表达正确率。历史召回格直接测试隔离的事件存储，不声称自然语言入口全链路覆盖。

## 评测审计

`baseline.json`、`after_s2.json`、`after_s3.json` 保留原始记录，但其故障轮复用了正常轮缓存，故障未被执行，**不能用于降级正确率前后比较**。现评测按故障状态隔离缓存并断言实际调用和路由。没有修复前源码快照，未伪造校正后的旧版百分比。修复前的红测试和日志证据仍有效。

`final_grounding.json` 对照的是既有 10 月 26 日原文快照，范围仅为 dev RAG 六份来源的逐字证据/引用元数据；不表示生成回答的语义评分。
