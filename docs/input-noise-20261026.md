# 换菜请求尾部误输入修复（2026-10-26）

截图输入：“换一道，不要刚才第二道。1”。回归测试复现了推荐状态被写入 `extra_constraints=['不要刚才第二道','1']`。尾部数字导致原本完整的“不要刚才第二道”无法作为序号排除条件识别；未知条件随后阻止推荐。规则提取没有将这句写入长期记忆。

## 处理规则

- 只对已经完整识别为换菜请求、在句末标点之后另有独立数字的情况进行容错。数字与明确换菜数量一致时，不将该重复数字作为新条件，并在回答中显示处理说明。
- 例如截图中的尾部“1”，以及同义的全角数字、空白和英文句号。原始用户输入照常保存，不改写历史消息。
- 若数字冲突或数量原本不明确，例如“换一道。2”“换一批。1”，先明确澄清，不执行换菜或应用待确认的偏好。
- 不删除带单位、温度、份数或后续限制的数字，也不承诺修正任意拼写错误。
- 保留完整的有效限制。例如“换一道，不要鸡蛋。1”仍排除鸡蛋，并只将该限制用于当前会话。
- 旧失败状态仅在上一条原始用户消息能证明同一误输入、且对应残留条件同时存在时修复。恢复时保留其他条件，并从该会话已推荐列表恢复序号引用；没有对应用户证据就不删除条件。

提示示例：已按“换一道，不要刚才第二道”处理，末尾单独的“1”未作为新条件。
