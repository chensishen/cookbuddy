# 菜谱浏览与同名来源选择

日期：2026-10-13。本批从模型问答调试转入使用入口完善，增加目录、分类分页和明确来源的选择流程。使用 conda `py3.12.11`，活动知识库仍为`bounded_v3`。

## 如何使用

打开[本地应用](http://127.0.0.1:8080)，在问题输入区域下方展开“浏览菜谱目录”。

1. 输入菜名或章节关键词，例如“蒸水蛋 操作”，选择“早餐”，点击“查找菜谱”。多个以空格分隔的词都必须在该菜的菜名或章节中出现。
2. 使用“上一页／下一页”浏览，每页12份来源；点击“查看原文”或“查看图片”会选择该条来源并提交本地工具查询。
3. 同名菜谱分别展示。陈皮排骨汤有两个原文件，不能按名字合并；可以先查看两份原文，再决定使用哪份。
4. 直接查询同名菜谱时，结果里显示“使用此来源”按钮，点击可继续原问题，无需复制文件路径。
5. “已选择来源”会显示在问题下方。切换到问答模式后，这个选择仍可约束后续问题；要问另一道菜，点击“取消来源选择”。问题与所选菜谱矛盾时，提交会被拒绝，不静默改成另一份配方。

目录、原文与图片是本地读取，不需要模型生成。目录查询只搜索菜名与章节，不判断食材齐全、替代关系、过敏或营养；食材推荐仍使用原有问答工具。

## 为什么按来源聚合

当前2074个文本块属于**372份来源、371个菜名、10类目录**。页面分别显示来源数和菜名数，避免把同名的两个原文件说成一个已合并配方。

目录以活动知识库的`source`聚合文本块，保留菜名、分类、章节和块数量。同一原文件的多个章节仅显示一张卡；同名但不同路径的文档显示两张。分类来自原仓库目录，不由模型猜测；`source_label`用于区分具体文件位置，不表示某份更新或更权威。

目录复用原有元信息，不另外生成向量或启用自动结构化草稿。卡片表示知识库有该来源，实际打开时继续执行原文、行号、版本与图片来源检查；浏览列表本身不是配方事实认证。

## 来源如何进入RAG与Agent

```mermaid
flowchart LR
    U[用户原问题] --> B[验证所选来源与菜名一致]
    S[目录或同名澄清按钮] --> B
    B --> E[保留全部问题条件并追加明确来源]
    E --> T[现有RAG或原文/图片工具]
    E --> A[单Agent/多Agent工具选择]
    A --> T
    T --> V[原有来源与回答检查]
    V --> R[展示原问题和对应文档证据]
```

HTTP提交新增可选`source`字段。服务先检查它属于当前知识库，再检查原问题、手填菜名以及已写出的其他路径是否冲突；失败时返回400，不进入队列。有效选择随原始问题一起保存在任务队列中。

执行层以完整原问题追加来源约束，不删去“没有某配料”“不要猜替代品”等条件。规划和RAG接收带来源的有效问题；页面与运行记录的`question`仍为用户原问题，`selected_source`单独记录选择。单Agent和LangChain的原有规范化逻辑可以恢复这份明确来源，避免规划模型提议另一道菜或另一份同名配方。

来源选择只适用于这道菜；带另一道菜名的复合问题需要取消选择后提问。路径目录名不会被误当作额外菜名，例如“鸡蛋羹/微波炉鸡蛋羹.md”。本批没有增加Agent工具或扩大其调用次数。

## 接口与实现

`GET /api/catalog?q=蒸水蛋%20操作&category=breakfast&offset=0&limit=12`

返回当前数据集／版本／集合、总来源与菜名数量、分类计数、匹配总数和当前页。接口使用原有本机Host和可选口令校验；分页上限50、关键词上限100字；非法分类、负偏移、重复／未知参数返回400。HTTP请求没有使用字符串拼接生成SQL或执行文件路径。

- [recipe_catalog.py](../scripts/recipe_catalog.py)：元信息聚合、搜索、分页和来源绑定。
- [serve_recipe_app.py](../scripts/serve_recipe_app.py)：目录API、提交前校验。
- [recipe_tools.py](../scripts/recipe_tools.py)：同名澄清提供可选择来源。
- [recipe_agent.py](../scripts/recipe_agent.py)：将选择传给现有工具与多Agent，保留原问题和运行记录。
- [页面](../app/index.html)：默认折叠目录，避免遮挡主问答入口；文本节点渲染、请求序号避免旧搜索结果覆盖新结果、来源选择可清除。

服务在启动时载入活动版本；发布另一知识库版本后应重启服务再读取目录。本批没有实现跨版本会话事务或拼音、别名、全文目录搜索。
