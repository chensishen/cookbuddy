# 基础牛奶面包简洁做法问答修复

原问题：基础牛奶面包怎么做？简洁说明，但保留用量、温度、时间和关键注意事项。

## 根因

原失败记录中，模型将原文第 165 行指向只覆盖 139–164 行的资料块，两次生成均使用相同错误编号。完整原文其实包含对应行。

原文兜底的请求识别仅覆盖裸“怎么做”以及明确包含“配方、步骤”的部分表达，漏掉了“简洁说明，但保留用量、温度、时间和关键注意事项”，导致原来的完整原文兜底未启用。

修复引用后第一次实测发现，依据复核输出达到 1024 token 上限而截断；这次虽成功使用原文兜底，但回答仍过长，因此继续修复复核输出配置。

## 修改

- 新增 `reference_spans.normalize_reference_spans`：仅在当前已提供的同一来源分块内，以绝对原文行号重新定位或拆分引用。引用正文须与当前原文逐字一致；缺行、越界、跨文件、伪造正文、非法编号均不修复，交由原有严格校验拒绝。
- 不修改生成结论或原文，不放宽依据支持与完整性复核。程序记录每次引用定位变更，便于诊断。
- 对明确菜名做法请求，单独识别简洁程度、用量、温度、时间、注意事项等展示要求；存在替代、改配方、特殊设备或未识别要求时仍保留原问答流程。
- 复核输出预算增至 2048 token，要求 reason 用 200 字以内概括；DeepSeek 非思考调用保留 JSON 格式约束。截断或非法输出仍拒绝发布。
- 完整原文兜底保留，以防模型总结无法通过核验；兜底不承诺与模型简洁总结等长。
