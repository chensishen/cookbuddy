# 食材识别与库存推荐修复（2026-10-26）

用户反馈：“我有鸡腿肉，推荐两道菜，说明还缺什么”返回“当前条件无法完整核实，请具体说明条件”。新增回归通过真实 prepare → 确定性工具路由 → 来源服务复现了相同回复。

根因是推荐解释器使用固定的 16 种食材词表，漏掉鸡腿肉；该库存声明被写入 `extra_constraints`，而推荐服务拒绝无法核实的额外条件。实际原料表能够推荐姜葱捞鸡、意式烤鸡等菜谱，“说明还缺什么”也能正常解析。

## 修复

- 使用当前活动菜谱中经原文校验的必备原料表建立食材识别词表，复用推荐时的原料解析；按数据文件版本缓存，不再只支持固定的 16 种食材。
- 库存、条件修改和简短食材表达共用识别范围，已有食材别名在进入任务时统一，避免马铃薯被重复列为缺少土豆。
- 鸡腿肉不归并为鸡腿或泛指鸡肉；带限制的库存推荐不再仅凭“计算”章节中的名称认定库存匹配。
- 带排除条件时仍按原料表输出已有、待补齐、可选和待核对条目。混合配料行无法准确拆分时保留待核对原文。
- 旧会话中已被误存为额外条件、现在可以完整理解的库存声明，会转换回有类型的食材条件；未知要求继续保留，不静默忽略。
- 无法理解的条件会逐条显示在回复中，方便用户修正，替代笼统失败提示。

没有修改用户原会话数据库记录或长期偏好；库存仍只用于当前会话。
