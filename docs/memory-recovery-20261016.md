# 记忆提取失败恢复验收（2026-10-16）

## 原因

对两条历史失败任务进行了不写库的复现。两次模型均返回 `finish_reason=length`，completion_tokens 均为 1200。输出 JSON 被截断，旧实现抛出通用 ValueError；队列随后以相同输出额度重复五次，最终失败。并非 PostgreSQL 或 Milvus 无法连接。

## 修复

- 记忆提取首次输出额度为 4096 token；提示词要求选取简短完整事实，避免复制整段菜谱。
- JSON 模型调用遇到 length 时，最多扩大额度重试一次，最高 8192 token；即使截断结果能够解析，也不采纳。
- 截断、未完成、非法 JSON、非对象结果使用固定错误码，队列保存具体原因，不记录模型正文或任意异常文本。
- 保留逐字证据校验、用户隔离、记忆版本和遗忘 epoch 防护。

## 验收

- 启用 PostgreSQL 集成测试，348 项测试全部通过；新增覆盖截断恢复、重试上限、拒收截断数据和安全错误记录。
- 重放前核对两条任务 epoch 仍有效；仅重置这两条失败任务，未重放已遗忘任务。
- 服务重启后，两条任务均完成：memory_tasks 从 37 done / 2 failed 变为 39 done，失败、等待和处理中数量均为 0。
- outbox 从 64 done 变为 78 done，失败、等待和处理中数量均为 0，补提取记忆已完成向量同步。
- 应用状态 ready，仍使用 deepseek-flash，完整问答模式开启。

外部模型仍可能出现网络或响应错误；超过有限重试后任务保留具体错误码供排查，不保证所有未来请求必定成功。
