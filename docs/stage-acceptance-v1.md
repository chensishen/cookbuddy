## 部署复现与失败保留

在临时目录复制代码、活动知识库和必要来源产物，不复制`.env`、Git历史或运行数据库。使用指定Python创建独立venv，重新安装`requirements-engineering.txt`，检查依赖一致性，再启动独立端口的本地服务，执行完整目录、同名来源、原文及图片演示。退出时清理临时服务和目录，保留验收记录；原有8080服务继续运行。

首轮依赖安装退出1，原记录保留。首轮未采集可脱敏的安装错误分类，因此原因未确定。补测增加不含索引地址与凭据的失败分类，随后安装与演示通过；不能将补测成功说成首轮成功，或推测已修复某个确定的网络故障。

这是同机独立环境和项目副本复现，复用了操作系统、Python基础解释器与可能已有的包／tokenizer缓存。检查器的环境标签来自指定基础conda环境，实际隔离运行的是venv。没有验证全新机器、全新Conda安装、Docker冷安装、不同操作系统OCR或远程部署。

## 复现入口

```sh
conda activate py3.12.11
python scripts/acceptance_closeout.py --part corpus
python scripts/acceptance_closeout.py --part deployment
python scripts/acceptance_closeout.py --part retrieval
python scripts/acceptance_closeout.py --part online
python -m unittest discover -s tests -q
```

每次生成新的`data/processed/stage-acceptance/<时间戳与随机标记>/`记录，不覆盖首轮。`deployment`重新安装依赖；`retrieval`和`online`会使用已配置API。默认分类检索逐类串行；在线问答仅一次串行和两次并发，控制测试规模。引用检查明确拒绝空引用、越界行号、改写和来源路径越界；检索候选命中不能掩盖重排后来源丢失。

本批新增4项回归测试，全项目**278项测试通过**。测试覆盖真实引用判断、非法路径／行号、空证据、单个变更来源独立记录，以及重排丢失目标来源的失败判断。

## 阶段结论与下一阶段

本地MVP功能与工程交付阶段可以收口。检索、重排、工具调用和运行入口有实现及对应证据，新增阶段验收不再将同一阶段无限延长。

生产上线仍需独立阶段：建立未参与开发的质量题集并标注章节证据，验证无菜名食材推荐；在全新机器或CI完成冷部署；按供应商配额开展更多轮次、不同并发档位的压测；确认账户、访问控制、跨主机队列、运维监测和部署目标。上述内容没有被本批有限验收替代。
