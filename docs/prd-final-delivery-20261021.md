## 扩展消融与原因分析

按用户选择保留严格RAG核心，增加完整生产E9与生产留一法；E8→E9还包含切块和生成/复核策略差异，不能只归因于原文直答。

当前核心复验 E0正确且完整5/6、E1为3/6、E8为6/6。生产层 E9为5/6；移除元数据过滤为4/6，遗漏了符合原文2星难度的汤羹；移除原文事实直答后，检索从3/6增为5/6，P95从9.532增至13.409秒。关闭别名还使别名原料题失去入口直答，并遗漏库存题最匹配的西红柿炒鸡蛋。这些只解释本开发集，不能宣称每个组件全库显著有效。逐方案见[扩展结果](expanded-ablation-results-20261021.md)和[核心复验](../data/processed/ablation-matrix-v1/run-v3/recovery-analysis.md)。

核心复验保留相同模型、索引、Top30→5与生成规则，仅把实验重排总预算由30秒延至90秒；42次重排准入中2次等待超过30秒，最长约49.5秒。此前短预算确实可能耗尽在本地队列，不等于模型HTTP读取慢或已确认的供应商账号限额。该实验时延不用于生产P95。

首次核心评分出现连接中断/超时，随后共享熔断阻止继续调用，只有30/96条有分数。初次报告与日志留存；冷却后单条恢复探测成功，再只补66条缺分，最终96/96评分齐全。成功分数未重算，答案未重新生成。16条完整result和审计输入一致的旧评分复用；评审账本记录84次实际HTTP尝试（80次成功、4次计费未知失败），没有把熔断拒绝当成新增API调用。

库存题还暴露出judge不稳定：E9与P-A6的答案、证据及审计哈希完全相同，却被分别判为未通过和通过。原回答已列出油盐缺料，并明确覆盖率只按原料表计算，judge仍称忽略油盐和步骤中的沸水。P-A6的6/6不能解释成“去掉Agent更准”。原始评分和反证均保留在生产报告目录 `judge-disagreement.json`，交由真人裁定。

无前缀对照实际为2011个唯一正文生成向量、映射到相同2074实体；其中63个实体共享重复的新输入，历史H2向量复用为0。初版计数把这63个实体误记成旧向量复用，已修正计数并保留原日志、计划和纠错审计。正文、向量和逐条读回核验未受影响。

## 运行、复验与回滚

当前应用：[cookbuddy](http://127.0.0.1:8080/)。

```sh
python scripts/project.py check --live
COOKBUDDY_INTEGRATION_TESTS=1 python -m unittest discover -s tests
node --test tests/test_answer_rendering.cjs
make eval-expanded PYTHON=/opt/anaconda3/envs/py3.12.11/bin/python
make eval-acceptance PYTHON=/opt/anaconda3/envs/py3.12.11/bin/python
```

`eval-expanded`在同一个新目录中依次生成生产层与严格核心的报告及独立评审，已有输出拒绝覆盖；可指定 `ABLATION_OUT=新目录`。该入口已做命令展开、参数及语法验证；本轮两阶段真实实验分别执行，没有为验证新包装入口而重复付费跑整套。缺评分或执行失败返回非零；低分基线仍按实记录，不把低分当作脚本异常。普通 `make eval` 保留现有封存/开发评测流程。严格验收目前返回2，表示仍有待验收项。

活动版本回滚仍读取 `data/processed/recipe_versions/bounded_v4_metadata/activation.json` 并调用 `knowledge_versions.rollback_active_version(change)` 后重启应用。函数核对当前版本，避免覆盖后续切换，不删除集合或历史证据。本轮没有激活消融集合。
