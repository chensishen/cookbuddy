# 问答耗时与核验调度优化

日期：2026-10-13。环境：conda `py3.12.11`。本批围绕模型调用开销、并行复核、超时后的原文降级完成，不修改知识库、Embedding空间或Rerank模型。

## 为什么这样改

上一批真实记录中，糖醋汁题总耗时55.713秒，其中模型阶段为资料判断10.739秒、生成3.397秒、依据核对16.283秒、完整性核对21.198秒。美式炒蛋可选配料题因修正调用七次模型，总耗时102.752秒。当前耗时主要在生成之外的判断与复核，不能仅靠调整Milvus索引解决。

原有代码只要唯一定位了菜谱，无论前置资料判断真假，都会尝试生成。因此在**唯一来源、已核验且已补齐该来源所有章节**时，前置调用不改变是否尝试生成，可以省去。完整来源不意味着所问属性存在：代码仍将“能否回答”保留为未知，生成后核验品牌等缺失属性。无明确菜名、来源不唯一或章节未补齐时，保留原有前置判断。

依据核对只看回答实际引用的摘录；完整性核对看原始问题和完整上下文。这两项互不依赖，可以同时执行，但最终仍要求证据支持与回答完整。它们不会共享同一份宽泛上下文，避免从未引用的段落替回答补证据。

## 实现与边界

- [qa_execution.py](../scripts/qa_execution.py)：完整来源判定、两个线程的复核调度、Context复制和模型阶段deadline。
- [generate_test_answer.py](../scripts/generate_test_answer.py)：接入执行策略，单独标记`availability`、`generation`、`repair_generation`、`support`、`completeness`和`absence`；匿名诊断记录增加开始／结束时间，可回查是否实际重叠。
- [recipe_tools.py](../scripts/recipe_tools.py)：可选答案缓存将执行策略纳入键；失败沿用明确标注的原文降级，不缓存降级为正确答案。

默认`RECIPE_QA_PROFILE=balanced`：符合条件时省前置调用、并行两项复核，并在模型阶段预留10秒供本地原文降级。用户总预算仍默认180秒，包含检索、排队和调用；预留发生在生成脚本进入模型阶段时，未改变总预算。剩余预算很短时不再额外扣除10秒。并行线程继承同一deadline和取消上下文，继续受已有跨进程模型并发／RPM／预算限制。

服务链路还在[ask_test_recipes.py](../scripts/ask_test_recipes.py)的生成子进程硬超时中预留这10秒，防止HTTP读取迟迟不结束时仅靠读取后检查deadline。子进程通过`RECIPE_QA_STAGE_RESERVED`告知生成脚本已扣除时间，避免重复扣除。最终蒸水蛋规则问答真实补测正常完成，执行记录确认硬阶段预留10秒；该规则题不调用生成模型。

`RECIPE_QA_PROFILE=serial`保留串行调度和前置调用，便于对照与回退；两种模式都继续使用相同的引用、限制强度、缺失属性和完整性检查。

并行遇到依据失败时，另一项完整性检查可能已经调用。这会在失败场景增加一次模型开销，换取正常场景较短的等待；不保证费用或吞吐一定改善。某项抛出异常时不交付成功答案，线程等待仍受模型deadline约束。远端已经收到的模型请求不会因此撤销计费。

## 真实固定输入对照

题集见[qa-latency-v1.json](../data/evaluation/qa-latency-v1.json)。每题两种策略共用同一个重排结果；生成答案缓存关闭，Embedding和Rerank保留现有缓存。因此比较的是**生成、核验与本地准备的墙钟耗时**，不是冷启动端到端耗时，也不是生产P95。每题每策略仅一次，部分题交替执行顺序；服务商负载及本地模型准入等待仍影响结果。

| 问题 | 串行秒／调用数 | 优化秒／调用数 | 来源审阅 |
|---|---:|---:|---|
| 糖醋汁五种用量与单位 | 68.094／4 | 45.068／3 | 两者均与原文相符 |
| 美式炒蛋可选配料 | 38.569／3 | 21.162／3 | 优化答对；串行产生虚构库存并被旧缺失判断错误放行，不能当作同质量速度比较 |
| 美式炒蛋牛奶品牌 | 39.399／3 | 15.016／2 | 两者都正确说明原文未指定品牌，状态为insufficient |

糖醋汁这一次减少约33.8%的墙钟时间；品牌题减少约61.9%。样本量不足以推广到其他问题，不汇总包含错误回答的速度平均数。优化版三题均满足本次来源预期，不代表全库问答质量已经验证。

时间戳显示糖醋汁两项复核实际重叠约26.699秒；可选配料题约14.972秒。品牌题是纯缺失属性的全文核验，不需要并行正面事实检查。

## 对照暴露的核验漏洞

串行可选配料回答额外编造“已有鸡蛋、牛奶、黄油和盐”。全文缺失核对模型错误标记`absence_only=true`，导致正面事实未被进一步核验。首轮原始记录保留，没有用后续结果覆盖。

现在只有程序保守识别出的纯缺失句式才允许走该快捷返回；含已有库存、可选结论、数值或做法的混合回答，即使模型标签为true，也须继续接受正面事实核对。新增测试直接注入错误模型标签，验证不能绕过引用检查。该句式判断是保守防线，不声称取代通用语义核验。

串行针对性复测仍未识别虚构库存，说明仅增加模型核对不够。因此又增加有限程序防线：用户没有明确声明库存时，生成结论不能附加“已有／你有”等个人食材断言。将本次真实错误文本回放到检查器，确认直接拒绝；该最后防线没有再重复做在线生成，不把回放单测说成线上模型已改正。

优化可选配料复测23.756秒，正常回答且摘录精确。草莓酱零糖安全控制遇到修正调用超时，170.13秒返回三段指定菜谱原文候选，摘录逐字核验通过，状态明确为降级。这次验证了总预算内可降级，也说明失败场景仍可能很慢；配置的45秒是网络等待上限参数，不等于包含准入、重试的整个阶段墙钟上限。

## 测试与复现

```sh
conda activate py3.12.11
python -m unittest discover -s tests -q
python scripts/evaluate_qa_latency.py
# 保留已有记录，重复执行不会覆盖对照。
RECIPE_QA_PROFILE=serial python scripts/serve_recipe_app.py --port 8081
```

新测试覆盖并行屏障、预算与取消在线程中不丢失、串行／并行判定一致、某一复核失败不发布、不同执行策略不混用答案缓存、真实本地模型socket超时后父预算仍可提供逐字原文降级。

最终**246项测试通过**，见[测试记录](../data/processed/qa-latency-v1/unit-tests.json)。最初短socket测试的20ms预算可能在HTTP发送前耗尽，已保留[观察记录](../data/processed/qa-latency-v1/unit-test-first-observation.json)，修正测试初始化与预算后验证实际socket超时，不将请求前耗尽误当作网络超时证据。

完整对照、逐题人工审阅与安全复测见[review.json](../data/processed/qa-latency-v1/review.json)。本批到此结束；下一阶段不继续无限调整复核提示词。剩余问题包括较长的失败路径、模型核验误判、并行对配额和费用的影响，以及尚未验证的多用户模型问答吞吐。

记录目录：[qa-latency-v1](../data/processed/qa-latency-v1/)。生成调用实际使用`Qwen/Qwen3-8B`，Embedding为`Qwen/Qwen3-VL-Embedding-8B`、Rerank为`Qwen/Qwen3-Reranker-8B`；本批没有更换模型。
