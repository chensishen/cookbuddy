# 问答调用诊断与真实链路复测

日期：2026-10-12。本批从已收束的五篇结构化候选转回正式文本 RAG。回答脚本现在为每次真实模型请求写一条独立诊断记录，字段仅含调用阶段、耗时、超时配置、结果类别、HTTP 状态（如有）、问题哈希和重排结果路径。阶段为 `availability`、`generation`、`repair_generation`、`review`。诊断文件不存请求正文、回答、密钥和认证头；已有完整执行记录仍按原机制留在本地，不因诊断而改变答案的证据门槛。

诊断位于 `data/processed/all_recipes/answer-results/model-attempts/`，成功回答的 `model_attempt_trace` 可指向对应文件；请求报错时终端也会显示诊断文件路径。每行一个 JSON 事件，`outcome` 区分 `ok`、`timeout`、`network_error`、`http_error` 和 `invalid_response`。这能确认在哪一阶段失败及当次耗时，不能仅凭一次超时推断服务商限流或网络故障。预设等待时间没有改动：普通生成 45 秒，资料判断和复核 90 秒。

均执行了 Embedding、Milvus、重排、自由生成与独立依据复核，使用同一篇蒸水蛋原文。以下是单次观察，不是全库准确率。
