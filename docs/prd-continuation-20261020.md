## 独立切块与前缀对照

新增 `scripts/evaluate_chunk_ablations.py`，隔离保存 H2 无前缀、H2 有前缀、现有 bounded 分块无前缀三份向量；生产 Milvus 不切换。H2 对照只按二级标题切分，保留三级标题和代码围栏内的伪标题，字符与行偏移可还原。两组 H2 的 chunk ID、内容和 gold 范围相同，只有向量输入前缀不同；前缀沿用实际生产格式，包含菜名、章节和路径。

对照使用原 96 道 gold 查询的保存向量，五种分块全部用精确余弦 Top-5，关闭标题/原料补召回、BM25 和重排。因此测量的是切块与前缀的检索贡献，不是完整端到端 A-3。原题已消费，只作为开发诊断，不重新标为盲测。报告必须覆盖全部 gold 查询，保存索引、题集、原报告与代码哈希，拒绝覆盖已有观测。

构建与对照命令（评测依赖已安装的 Python 环境）：

```sh
python scripts/evaluate_chunk_ablations.py build --variant h2_plain
python scripts/evaluate_chunk_ablations.py build --variant h2_prefix
python scripts/evaluate_chunk_ablations.py build --variant bounded_plain
python scripts/evaluate_chunk_ablations.py compare --report data/processed/prd-acceptance/20261020T061036740626Z/report.json
```

构建可恢复已保存批次；同目录来源或模型变化会被拒绝。每批最多 8 条，保持原有准入与向量响应完整性检查；向量索引与 API 用量账本在 `data/processed/chunk-ablations-v1/`。

## 第二份测试之后的修复与复核

- Agent 的“之前”范围检查：只有原文工具完整识别的字面答案可以直接结束；“之前说过”等历史问题及图片、记忆组合要求仍允许后续工具。准备食材问题不再多调用一次规划。
- 规划失败且没有工具结果时，仅尝试严格匹配的本地原文字面事实，并检查预算与来源硬约束；返回显式 degraded 摘录，保留原规划错误、partial 状态和降级步骤。没有把固定规则冒充成功规划，复杂问题仍明确不可用。
- judge 空回答误判：观察到独立模型把空回答当作正确完整。现在程序先检查非空回答与可评审执行状态，空白/失败计零；原始正分与响应保留为诊断。`report-before-execution-eligibility.json` 保留更正前报告。汇总同时报告有效评审覆盖和失败数。
- 完成率判定同时检查 Agent 顶层状态；工具 verified 后发生规划错误，仍为执行失败。语义评审与整次执行完成率分开，防止正确工具结果掩盖失败。

修复后使用已消费旧题进行真实 Agent 回归：响油鳝丝准备问题1.312秒，炒糖色流程1.210秒；两次均completed、一次规划、5/5引用元数据正确。证据为 `continued-20261020/final-agent-live-regression.json`。它们不并入封存分数，也不作为新盲测。

正式测量之后的独立最小请求返回HTTP 200、正常结束，8个实际token；记录在 `provider-probe.json`。这只表明探测时服务可用，不能反推之前429的具体配额，也不认证持续可用性。用户已明确将RPM、TPM与单次成本上限记为“未定”，完整成本可接受性保持待确认，见 `constraints.json`。
