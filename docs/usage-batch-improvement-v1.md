# 使用验收第一批：三类问题成批改善

2026-10-12。针对[第一批六场景验收](usage-acceptance-v1.md)中的三类未满足项，一次完成来源绑定回答、测试和真实链路复测。原始失败与超时记录继续保留，新运行在 `data/evaluation/usage-batch-fix-v1/`，选定最终记录及逐字引用检查见 `summary.json`。

| 问题 | 原结果 | 本次实际结果 | 回答方式 |
|---|---|---|---|
| 可乐鸡翅处理鸡翅及加可乐时机 | 首答遗漏后修正请求超时 | `verified`，摘录操作第1–4步，明确第4步煎至金黄后倒入可乐 | `source_process_excerpt` |
| 酸辣土豆丝的调料 | 把青红椒归为调料，漏计算章节食用油 | `verified`，调味料为生抽、陈醋、盐；青红椒等列在其他配料；提示计算章节另有食用油10–15ml | `source_ingredient_query` |
| 已有豆腐、猪肉末做麻婆豆腐还需确认配料 | 草稿漏料，模型复核误判“肉糜也行” | `verified`，保留豆腐品种、五花肉/肉糜的待确认关系，列出其余原料、可选小米椒、工具，另列计算/操作的名称差异 | `ingredient_table_comparison` |

这三项都实际运行了文本 Embedding、Milvus 检索、Qwen3-Reranker-8B 重排及来源核对。最终回答分别由连续原文摘录、有限调料分类和原料表程序比较生成，**没有调用 Qwen3-8B 回答或语义复核模型**，因此结果不能归因于模型生成能力提升。最终5处引用均与当前原文件行逐字一致；逐字一致本身不证明所有表达适用于全库。项目158项代码测试通过。

实现范围受限：连续摘录只接受明确单菜名、唯一操作章节、连续且至多5个步骤的“如何处理 X、何时加入 Y”问法；答案会保留完整原文步骤，可能较长。调料分类只覆盖有限已知名称；遇到未识别条目回到一般问答。明确库存问题现在也可触发原料表逐项比较；“豆腐”不能直接当成“内脂豆腐”，猪肉末也不擅自等同于原文肉糜。计算和操作章节提到的额外配料按来源标为待确认，不自动判为必需。

修正回答请求的 API 超时没有被普遍解决；模型自由生成的完整性与复核误判仍是一般问题。本批次只证明上述三种受限来源路径可以绕开这些失败。第一批六场景中，另外三项原文、图片不足、米饭品牌不足沿用既有验收结果；按助手对原文的检查，六项目前均满足各自预期，但尚未经用户人工复核，不构成全库准确率。
