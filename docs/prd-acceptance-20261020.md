# PRD 整体改进与验收（2026-10-20）

依据：[PRD v1.1](../PRD_菜谱RAG_Agent.md)。结论：**部分通过，尚未达到完整PRD验收条件**。本轮在现有系统上补齐条件推荐、重排故障处理与验收流程，不重建活动知识库。

## 本轮改进

- 原料表覆盖率推荐支持明确分类和数字难度上限，例如“我有鸡蛋和番茄，推荐3道素菜，难度不超过2星”。分类取原库目录，难度取原文星级；未知难度不满足显式难度上限。初轮实测发现“相同覆盖率先按缺料数排序”会挤出同时匹配鸡蛋和番茄的菜，因此恢复既有的匹配库存种数优先，并增加反例回归。按照覆盖率、匹配库存种数、缺料数、难度排序，保留未解析条目与工具。原库“素菜”分类不等于纯素或过敏安全认证。
- 不辣、过敏、低热量、多个分类及未支持的难度表达不会被删除后当作简单库存问题回答，继续由原有完整流程处理。此改进接入 `query_recipes` 的原料表推荐分支；不代表所有会话状态组合和偏好推荐都已有统一元数据过滤。
- 推荐引用覆盖原料表的所有分块，显式难度条件另附原文难度行，避免只有第一块被引用。两个真实活动库查询分别返回3道与2道菜，10条引用全部逐字还原，记录见[条件推荐实测](../data/processed/prd-acceptance/filtered-recommendations-20261020.json)。
- 重排对 HTTP 408、429、500、502、503、504 保留原候选顺序并记录具体错误码；认证错误单独报错；父请求取消或预算耗尽仍会终止。原来 `HTTPError` 作为 `URLError` 的子类会被笼统记录，401也被当作可降级连接错误，现已区分。
- 新增固定工作流与完整 Agent 的同题对照，使用相同菜谱工具，直接测量省去规划模型的影响。该对照是 A-6 的初步证据，不等于全套增量、留一法及参数消融。
- `make eval` 固定本轮报告路径，judge/Ragas不再各自读取可变的 `latest.json`；评审失败后仍生成门槛报告并保留非零执行退出码。新增 `make eval-acceptance`：有任何未达标或待验收项目时退出码为2。执行成功与PRD达标分别报告。

## 验收口径

沿用原料表推荐的既有口径：未明确拥有的油盐等调料保持“库存未知”。PRD 3.2要求缺料提示、5.6提出默认拥有调料，两处口径不同；本轮保留既有保守行为，没有新增用户库存假设。

本轮使用既有10题开发诊断集，其中8题有检索gold、5题做回答对照；新增方案后共20组回答。没有把已用于开发的题目重新命名为盲测。固定工作流排在完整Agent之后，同轮可能复用Embedding/重排缓存；延迟差包含规划调用与缓存顺序影响，不能当作严格的冷缓存因果实验或生产SLA。

## 复跑

```sh
COOKBUDDY_INTEGRATION_TESTS=1 /opt/anaconda3/envs/py3.12.11/bin/python -m unittest discover -s tests
node --test tests/test_answer_rendering.cjs
make eval PYTHON=/opt/anaconda3/envs/py3.12.11/bin/python
make eval-acceptance PYTHON=/opt/anaconda3/envs/py3.12.11/bin/python
```

`make eval` 的退出码只表示评测流程是否完整执行。严格门槛另见同轮 `acceptance.json` / `acceptance.md`；`make eval-acceptance`有未完成项时返回2，make可能将其包装成自己的非零退出码。人工盲评需要真实独立评审参与，不能由本次自动化回归或同模型judge代替。
