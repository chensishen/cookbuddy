# 受控端到端消融协议（2026-10-21）

固定题集 `data/evaluation/controlled-matrix-dev-v1.json`：6题（4道库内、2道库外），覆盖事实、别名、库存、明确元数据约束和拒答。属于开发诊断，不能推断全库准确率或替代封存测试。每题运行15种组件配置，并单列未改动生产Agent，共96条回答。

## 固定条件与开关

所有受控方案使用当前生产聊天模型、同一JSON原文引用生成器、相同最终K=5。E1使用独立512-token无前缀稠密索引；E2使用独立H2无前缀索引；E3换成独立H2有前缀索引。E4加入overview召回投影及食材别名归一化；E5加入BM25与RRF；E6加入真实模型提取的约束和元数据过滤；E7对Top30候选真实重排；E8加入真实模型工具调用编排。

A-1至A-6分别仅关闭E8的重排、混合检索、前缀、过滤、归一化、Agent。配置字典逐项可查，单元测试验证每个留一方案恰好只改一个组件。

Query原文在生成与评审中保持不变。原始/归一化查询向量提前真实生成、共同复用；每题真实约束提取结果同样固定后供有过滤的方案复用。这样避免把请求顺序或提取随机性当成组件效果；共享预计算使本实验时延**不能直接用于生产端到端P95门槛**。

实验使用同一精确余弦计算，隔离ANN误差。overview索引只参与召回，其Embedding输入包含派生分类/难度/食材；交给生成器的 `content` 仍是对应原始H2食材表或简介。overview和原H2映射为同一个证据节点，候选去重，避免重复占用Top5。无前缀与未归一化overview分别独立向量化；不从已有融合分数删行伪造消融。

跨切块粒度检索Gold使用相同原文范围映射（至少32字符交集，短Gold按其全文长度），overview映射到原证据节点。所有引用重新验证唯一原文摘录与字符偏移。

## 生产系统与受控E8的区别

受控E8的Agent真实选择工具，调用的检索/生成函数与其余受控方案相同。它保留 `baseline_unreviewed`，表示生成回答待独立评审；实验只补充“查询已经完成”的停止判定，不将回答改标为verified。生产Agent保持原工具、原文直答、语义复核、降级等策略，单列 `full_agent`，不与受控E8混为同一系统。

因此本次可以补齐**受控组件矩阵的端到端执行证据**，不能据此宣称生产系统所有留一法均已得到无混杂的统计认证。题集仅4道库内题，重排收益检验没有足够统计能力，已有正式未达标结论继续保留。

## 评审与失败规则

所有可评回答由独立Qwen评审模型核对正确、完整与引用支持；失败和缺失评审留在分母中。五项Ragas用于核心对照E0、E1、E8及生产Agent，范围明确记录；其余组件方案保留逐题独立评审及引用规则指标。Closed-book未收到检索资料，其上下文类指标为N/A；不得把Gold审计资料当成真实检索上下文。

代码运行前后哈希、题集哈希、索引哈希、原始模型输出、实际HTTP用量和失败类型随报告保存。费用缺少完整价格/计费或用户预算时保持未知。

第一次试运行的29条记录保存在 `data/processed/ablation-matrix-v1/run/`。发现受控“未评审”标签未触发任务完成边界，可能诱发重复查询，因协议问题停止，未进入最终比较。修正只针对实验停止策略；原记录和旧协议源代码保留。新运行位于 `run-v2/`，不覆盖试运行。

运行入口：`scripts/ablation_indexes.py`、`scripts/evaluate_full_matrix.py`；独立评审沿用 `scripts/review_prd_eval.py`；五项指标沿用 `scripts/evaluate_ragas.py`，新增明确方案范围和实际受控上下文兼容。
