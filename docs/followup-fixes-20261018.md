# 复合推荐与材料核对的补充修复

复查前次改动后，发现两个入口未覆盖：

1. “介绍一下每道菜”仍会进入 `extra_constraints`，使后续选菜绕过已有筛选。
2. 原有结构化库存样本已经分标题，但 `ingredient_condition_rules` 的缺料、可选材料、缺工具等判断仍输出长段落。

本次改动：

- 将完整匹配的菜品介绍请求归入回答字段；“介绍每道菜的热量”等未知要求继续保留，不擅自忽略。
- 兼容转换旧状态中的同类介绍要求，保持实际食材、口味和做法限制。
- 新增 `inventory_display.inventory_sections`，让结构化库存比较和有限食材条件规则共用展示契约。每个标题下的结论仍绑定当前原文定位。
- 条件判断分别展示已有、明确缺少、尚未说明、可选和工具项；未把未知库存改成明确缺料，也未把缺工具的要求改成材料齐全即可制作。
- 材料可行性和明确缺料问法在查询时也隐藏执行阶段，只显示“正在查询…”。普通推荐的执行记录仍可折叠查看。
