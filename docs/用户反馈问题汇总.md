# CookBuddy 用户反馈问题汇总

本文记录用户报告过的现象与期望。列入本文不等于当前版本仍存在问题；复测状态见 [回归复测清单与记录](回归复测清单与记录.md)。

| 编号 | 报告过的现象 | 期望 |
| --- | --- | --- |
| F01 | 「你是谁」进入知识库检索；换说法、输入错字或句尾多一个数字就答偏；「尽量简单」「今晚两个人」「我只有鸡腿肉」被反复要求确认。 | 信息足够就直接回答；明显错字可结合上下文纠正；只有会改变结果的歧义才追问。 |
| F02 | 「这道还缺什么」被问要看哪个章节，点「操作」又被理解为改选菜条件；连续对话里更新库存或换菜后丢失原有条件。 | 承接当前菜和列表；移除用完的食材、加入新食材、保留其他库存与数量；指定换第二道时保留第一道，按要求简短说明理由。 |
| F03 | 要两道却只给一道；番茄和马铃薯只匹配到番茄；冰箱、数量说明被列为缺料。 | 优先覆盖手边食材，逐道列出待备食材；分开显示工具及待核对事项；候选不足时说明。 |
| F04 | 早餐、午餐和晚餐推荐相似；同样的菜单反复出现；安排一餐需要反复补条件；有时间预算仍无法合理搭配，「三菜一汤」可能没汤。 | 按餐次、整餐耗时和菜单结构选菜；条件可分轮补充，够用即答；无法配齐时给出明确原因及可行替代。 |
| F05 | 请求完整原文和图片却被问选哪个章节；只看酵头图片时被当成菜名；从酵头转问烘烤仍回答发酵。 | 延续当前菜谱，按要求切换范围和输出；酵头问题区分静置与发酵，烘烤问题回答温度、时间及原文有无调整办法，并提供依据。 |
| F06 | 人数、时长、难度被记成长期偏好；记住后查询答成自我介绍；忘记具体一项仍要确认；关闭后无法正常恢复；新旧口味冲突或推荐未采用偏好。 | 人数、时长、难度只用于当前任务；明确点名删除就只删该项；查看、清除、关闭和重新开启都有明确结果；推荐和菜单应用有效偏好，处理冲突。 |
| F07 | 第一条回答或各流程的耗时不显示；推荐卡片不能打开详情或弹窗太窄。 | 首问与后续均显示总耗时，展开能看到各步骤耗时；推荐卡可打开宽度合适的菜谱详情。 |
| F08 | 理解服务不可用时早餐直接失败、午餐能降级回答；历史对话曾提示会话服务不可用。 | 明确请求尽量走可核实的本地路径，按餐次回答；数据库或其他依赖异常时显示有用状态，恢复后会话可用。 |
