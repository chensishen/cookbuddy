# 记忆机制改进与验收（2026-10-16）

本轮完成此前讨论的任务保存解耦、减少重复输出、原文片段编号选择、长内容分批处理和失败批次恢复。替代此前单纯增大记忆提取输出额度的实现。

## 当前流程

1. 已完成且含已核验证据的任务直接写入 PostgreSQL，按 job_id 幂等保存，独立于模型提取结果。
2. 用户画像仅从当前用户明确陈述生成候选。模型返回候选编号、字段和评分，程序回填原句；保留字段白名单、假设/提问过滤、消息先后顺序和遗忘 epoch 检查。
3. 知识候选只来自 verified / verified_source 的原文证据；程序检查文件路径、来源行范围和逐字内容。遍历全部证据，取消原先只取前 8 条的限制。
4. 原文按完整段落生成候选；长段落在句子或换行边界拆分，每个候选最多 1000 字。无法按这些边界拆分的超长单句明确报错，不截断后假装成功。每批最多 6 个候选，序列化大小约束为 4800 字符。模型每批最多选 4 条知识。
5. 模型仅输出编号和评分，禁止返回正文和来源。程序拒绝不存在的编号、重复知识编号、重复画像字段、非法评分及额外字段；保存时从原始候选回填正文、行号和文件哈希，再次检查文件未变化。
6. 每批成功后持久保存进度。失败批次保留安全错误码，其他批次仍可处理；任务有限重试时只调用未完成批次，成功批次不会重新调用模型。进度可在服务重启后继续使用。
7. 原有 outbox 负责向量同步；检索时 PostgreSQL 的状态和版本仍为准，过期、遗忘或来源变更的记忆不能注入 Prompt。

每批初始输出额度为 1200 token，截断时最多扩大一次至 2400。当前通过更小的选择结果避免长正文输出，保留有限重试兜底。

## 结果与错误区分

`memory_tasks.extraction_progress` 保存批次状态，包含 `saved`（有通过校验的记忆）、`no_memory`（无达到保存条件的选择）、`no_candidates`（无候选）和 `failed`（提取或校验失败）。规划状态 `ready` 仅为候选规划信息，不是模型处理成功。

失败不会转换成空记忆成功。错误码只保存固定模型错误或异常类型，不保存模型正文、认证头或任意异常文本。提取进度属于用户隔离的数据，主动遗忘时一并清理；旧 epoch 无法补写进度或复活记忆。

## 运行与复跑

在项目的 py3.12.11 环境下：

```sh
python scripts/cookbuddy_manage.py init
python scripts/cookbuddy_manage.py health
COOKBUDDY_INTEGRATION_TESTS=1 python -m unittest discover -s tests
python scripts/accept_memory_extraction.py --live
```

初始化会应用新增的 003 迁移，不清空已有历史或记忆。health 显示队列及批次汇总；retry-failed 继续沿用失败任务有限重试，并保留已完成的批次进度。真实验收会调用已配置的外部模型，使用独立用户并清理测试数据；建议在应用停止时运行，避免后台 worker 处理测试 outbox。

## 验收边界

分批增加调用次数，不能根据单个样本宣称所有请求都更快或总费用更低。当前验证了较短输出、失败恢复及来源一致性；记忆选择的召回率、评分校准和大规模并发仍需独立题集评估。本轮没有更换菜谱向量空间或重新提取用户历史记录。
