# Agent检索过滤参数接入（2026-10-20）

本步将上一轮检索参数接入经典工具调用Agent和LangChain专员工具。`query_recipes` 可接收可选 `category`、`max_difficulty`，继续保留用户完整原始问题。过滤条件贯穿本地直答、推荐、缓存、检索子进程与故障候选；返回前检查来源范围。完整PRD仍为部分通过。

## 接口与约束

例如工具调用：

```json
{"question":"我有鸡蛋，推荐汤羹，难度不超过2星","category":"soup","max_difficulty":2}
```

- 经典工具JSON Schema提供分类枚举及整数范围；LangChain工具提供对应可选参数，难度使用严格整数类型。统一分派再次校验，拒绝未知分类、布尔值、字符串难度或超出1–5的值。
- 工具提示要求仅填写用户明确要求的条件，不猜测限制。恢复被模型缩写的问题时保留合法过滤参数。本步交付时未测真实规划模型；后续经典Agent首轮小样本结果见 [真实规划诊断](agent-filter-planning-20261020.md)，仍未新增确定性的自然语言约束抽取器。
- 使用请求局部的ContextVar传递过滤条件，经 `run_stage` 显式序列化为 `RECIPE_SEARCH_FILTERS` 传入子进程；环境中的非法字段同样拒绝。上下文在异常退出后恢复，并发请求互不污染。
- 原文事实直答、食材推荐与同名来源澄清均使用筛选后的块。用户点名菜谱不在指定范围，或没有合格来源时，提前返回不足说明。
- 回答缓存键加入过滤条件；故障后的BM25原文候选也在过滤范围内。与既有记忆硬限制继续取交集。
- 最终检查引用、证据、图片、推荐、来源选择、原文展示及结构化回答锚点。范围外内容整体拒绝；带过滤条件但没有来源的“已核验”回答也拒绝，避免留下描述被移除菜谱的正文。

本步不改变生产模型、账号配额、活动向量或集合字段。
