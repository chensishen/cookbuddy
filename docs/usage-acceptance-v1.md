# 新增菜谱使用验收：第一批六个场景

日期：2026-10-12。按 [阶段收尾与验收清单](stage-closeout-and-usage.md) 固定的六个场景执行。四道新问答走真实文本 Embedding、Milvus、重排和回答链路；原文与图片查询使用本地工具；原文和无图片提示另在本地网页实际操作。此记录是助手对原文的检查，尚未经用户人工核对，不能代表全库准确率。

| 场景 | 实际结果 | 验收判断 |
|---|---|---|
| 查看可乐鸡翅原文 | 后端返回5个章节、完整原文；网页显示章节、行号和来源链接 | 符合预期 |

`data/evaluation/usage-acceptance-v1/` 中保留首次四道问答、可乐鸡翅一次补测、本地工具运行记录和 `summary.json`。机械检查7处展示的原文摘录均与当前源文件对应行逐字一致；逐字匹配不能证明分类和缺料判断正确。可乐鸡翅做法题因两次接口超时未生成最终答案，未计入语义通过率。没有为追求全绿继续重试，也没有更改原菜谱、Milvus集合或模型选择。

网页在 `http://127.0.0.1:8080/` 实际显示372道菜谱、354张本地图片；“查看可乐鸡翅原文”呈现完整章节、真实行号和来源；“查看可乐鸡翅图片”呈现资料不足。页面操作验证的是显示与提交流程，不证明模型问答可用性。

本批次的下一处理顺序：先查明回答生成时接口读取超时的频率和阶段；随后以原文完整原料表为依据修复库存推荐遗漏，并让复核能识别原文中“肉糜也行”的替代说明；调料分类和计算章节食用油作为同一类查询质量问题处理。只在这些通用问题得到验证后再补测对应场景，避免把六道验收题写成特例规则。

## 可乐鸡翅生成超时定位（2026-10-12 后续检查）

读取两次完整链路记录和已保存的拒绝草稿可确认：检索、重排均已完成；回答模型第一次均只提到鸡翅焯煮或沥水，漏掉改刀腌制、煎制以及“煎至金黄后倒入可乐”的时机，因此来源/完整性复核正确拒绝。修正请求在读取模型 API 响应时超时，未生成可供验收的完整答案。第三次仅复用第二次重排结果测试回答生成：明确提示分别回答两个问点，并把修正请求读取等待从45秒临时延至90秒；第一次仍遗漏加入可乐的时机，修正请求仍超时。临时改动已撤回，项目测试恢复为152项通过。第三次拒绝草稿位于 `data/processed/all_recipes/answer-results/rejected/20261012T081051622957Z-8425bc802a58477c854c29add5b07faf.json`；第三次超时没有生成回答结果文件。

因此当前可确认两项独立问题：模型首次生成对多问点回答不完整，修正请求读取超时。尚不能从这些记录判断服务商限流、网络波动或模型处理耗时各占多少，也不能宣称延长等待能修复。此场景继续标为“阻断”，不计通过；下一次处理应记录匿名阶段耗时/超时类型并评估更小的修正上下文，先在非验收问题中试验，再回到这道题验证。当前不继续重复调用同一问题。
